# act_runner — bashy verified build

bashy runs the Gitea Actions runner behind `bashy act_runner` only from a
**bashy-CI-built, keylessly Sigstore-signed build of the official upstream
release tag**. This directory is the declaration for that build. `fork/` is
installed as the `bashy-build` branch of `github.com/qiangli/act_runner`; it
carries no upstream source — the workflow clones the upstream tag fresh on
every run.

| License at the tag | **MIT** (`LICENSE`, verified at `v5.0.0`) |

## The non-GitHub upstream

act_runner is the first tool in `builds/` whose upstream does not live on
GitHub. Its home is `gitea.com`, and its prebuilt binaries are published on
`dl.gitea.com` — which is why yoke resolves it with a `binmgr.URLSpec` rather
than a `GitHubSpec`.

`render.sh` **derives** the forge from `UPSTREAM_REPO` (it is not separately
declared, so the two cannot disagree). A non-`github.com` host changes exactly
two things in the rendered workflow:

- the upstream checkout becomes
  `git clone --depth 1 --single-branch --branch <tag> "$UPSTREAM_REPO" src`
  instead of `actions/checkout` with `repository:`, and
- the `pin` job queries `UPSTREAM_API_BASE` (`https://gitea.com/api/v1`)
  instead of `https://api.github.com`. Gitea serves the identical
  `/repos/SLUG/releases/tags/TAG` shape with the same `.draft` and
  `.prerelease` fields, so the draft/pre-release gate is unchanged.

**The pin gate is identical.** The shipped `bashy-build/verify-pin.sh` still
demands that `src/`'s `HEAD` *and* `refs/tags/<tag>` both resolve to
`UPSTREAM_COMMIT` over a pristine tree — a shallow single-branch clone carries
the tag ref, so a second forge buys no weaker provenance than
`actions/checkout` does. The fork itself is still on GitHub and still checked
out with `actions/checkout`. See `../README.md` §Non-GitHub upstreams.

### The upstream rename

Upstream **renamed the repository** `gitea/act_runner` → `gitea/runner`; the
project and its binary are now called `gitea-runner` (`Makefile`
`EXECUTABLE := gitea-runner`, and the root command's `Use` is `gitea-runner`).
`gitea.com` 301-redirects the old path, but the canonical name is what is
pinned here, so neither the clone nor the release-API call depends on a
redirect resolving the same way forever.

The **bashy tool keeps the name `act_runner`**: that is what yoke's binmgr
calls it, what `FORK_REPO=qiangli/act_runner` is, and what the release assets
are named. Only `UPSTREAM_REPO` and `UPSTREAM_SLUG` follow upstream.

## Build configuration, and how it differs from upstream

Upstream publishes its binaries with goreleaser (`.goreleaser.yaml`):

| | upstream release | bashy build |
|---|---|---|
| `CGO_ENABLED` | `0` (`builds[].env`) | **same** |
| `-trimpath` | `builds[].flags` | **same** |
| `-ldflags` | `-s -w -X …/internal/pkg/ver.version={{ .Summary }}` (a `git describe`) | `-s -w -buildid= -X …/internal/pkg/ver.version=` **the pinned tag** |
| build tags | none | **same** (none) |
| `GO_PACKAGE` | `.` (`main.go` at the module root) | **same** |
| platforms | darwin/linux/windows/freebsd × amd64/arm/arm64/loong64/s390x/riscv64 | the four bashy ships: linux amd64/arm64, darwin amd64/arm64 (see `../README.md` §Windows legs) |
| asset names | `gitea-runner-<version>-<os>-<arch>` | `act_runner-<os>-<arch>` (yoke's binmgr name) |

Upstream's `Makefile` stamps the same `ver.version` variable; using the pinned
tag instead of `git describe` is what keeps the stamp reproducible, since the
workflow's shallow clone has no describe-able history.

## Security override: 10 reachable findings, 0 waivers

`GO_TOOLCHAIN_SECURITY_OVERRIDE=1.27.2`. v5.0.0's `go.mod` says `go 1.27` with
`toolchain go1.27.1`, and govulncheck reports **10 reachable stdlib
vulnerabilities** in `go1.27.1`: `GO-2026-6603`, `GO-2026-6605` and
`GO-2026-6607` … `GO-2026-6613`, `GO-2026-6617`. Every one is fixed in
`go1.27.2`, the newest patch of the tag's own Go minor, so the build and the
audit both run on it. Reachable vulnerabilities are never waived, and no later
upstream tag exists yet; `files/vuln-ignore` is empty.

Under `go1.27.2` govulncheck reports **no reachable vulnerability at all** — in
the stdlib or in any dependency — so `GO_SECURITY_OVERRIDES` (the module half)
is empty for this tool. The override retires itself the moment an upstream tag
ships on `go1.27.2` or later.

## No tracking: every knob at v5.0.0

act_runner has **no usage reporting and no update check**. Almost everything it
talks to is configured by the operator: the Gitea instance it registers with,
the Docker daemon it runs jobs on, an S3 cache bucket if one is set. It has
exactly **one unconfigured outbound call**, and it is the reason this
declaration ships a config file at all.

| Knob | Upstream source line | Upstream default | bashy |
|---|---|---|---|
| `cache.host` | `config.example.yaml` "Leave empty to detect automatically"; `act/artifactcache/handler.go:159` | **empty → `common.GetOutboundIP()`, which dials `8.8.8.8:80`** (`act/common/outbound_ip.go:24`) | **`127.0.0.1`** |
| `cache.port` | `config.example.yaml` | `0` (random free port) | fixed, so the gate and the allowlist can name it |
| `cache.dir` | `config.example.yaml` | `$HOME/.cache/actcache` | bashy's own state dir |
| `cache.external_secret` | `cache-server.go` (required for `cache-server`) | empty | generated per deployment, never a shipped constant |
| `cache.offline_mode` | `config.example.yaml` | `false` | **`true`** — reuse a cached action instead of re-fetching it from the remote on every job |
| `runner.insecure` | `config.example.yaml` | `false` | `false` (pinned, so a future default change cannot weaken TLS verification) |
| `log.level` | `config.example.yaml` | `info` | `info` (pinned explicitly) |

**The `cache.host` knob is the whole point.** `gitea-runner cache-server` tells
job containers where to reach it via `Handler.ExternalURL()`, and to learn its
own address with `OutboundIP` unset it opens a UDP socket to Google's resolver
at `8.8.8.8:80` — a real connect to a third party on every start. It is not a
DNS lookup the shared verdict would forgive as local IPC, and
`files/no-egress-test.sh` fails the build if a future pin or config drift
reintroduces it. Pinning the host removes the probe outright, and is correct
for bashy anyway, whose jobs reach the cache over loopback.

Two documented remote defaults are **not** bashy's to pin here, because they
are job-image policy rather than runner tracking: `container.default_image`
and the `runner.labels` image list point at `docker.gitea.com/runner-images:*`,
and `container.force_pull`/the actions URL rewrite govern where job images and
actions come from. They are resolved per deployment by whoever registers the
runner.

`files/no-tracking.env` clears `HTTP_PROXY`/`HTTPS_PROXY`/`ALL_PROXY` (Go's
`net/http` honours them, so an operator shell could otherwise hand the runner
an egress path) and pins `NO_PROXY` to loopback.

### OpenTelemetry

The pinned release links no OpenTelemetry SDK — v5.0.0's `go.mod` requires no
`go.opentelemetry.io` module, and the runner's own observability is logrus
logging plus whatever the Gitea instance records. `files/otel.env` still sets
`OTEL_SDK_DISABLED=true`, all three exporters to `none`, and pins the general
and per-signal endpoints at `http://127.0.0.1:31415` — byte-for-byte the
destinations yoke's `external/internal/serviceenv` `LocalOTLP()` installs, so
if a future pin ever does export, it can only reach bashy's own collector.

### No-egress gate

`daemon` and `register` are the wrong subjects for this gate: both are
*supposed* to reach their configured Gitea instance, and neither starts without
one. So `files/no-egress-test.sh` runs the subcommands that need nothing
external — `--version`, `config generate`, `config get cache.host` — and then
starts `cache-server`, which is a real long-running HTTP listener and the one
part of the runner with an unconfigured outbound call to remove. It probes the
cache API and the internal registration endpoint over loopback (both reject an
unauthorized probe, which is fine — only the destination is judged), idles
30 s, probes again and stops it. The allowed destinations are
`127.0.0.1:EGRESS_PORT` (default 18088) and `127.0.0.1:31415`.

- **Linux (authoritative):** a fresh network namespace (`sudo unshare --net`,
  only `lo`), traced with `strace -f -e
  trace=connect,sendto,sendmsg,sendmmsg` and run unprivileged via `setpriv`.
  The verdict is the shared `egress-verdict.sh`: any AF_INET/AF_INET6 attempt
  other than loopback to those two ports — including DNS, the `8.8.8.8:80`
  probe above, and attempts the namespace makes fail — fails the build.
- **macOS:** `sandbox-exec` denies all `network-outbound` except
  `localhost:18088` and `localhost:31415`, and denies the mDNSResponder
  socket; any Sandbox deny for the process in the unified log fails the build.

## Audit

The `audit` job runs the pinned `govulncheck` (`v1.9.0`) in source mode over
`./...` and fails on any vulnerability that is **reachable** — one whose first
trace frame names a called function — unless it is listed with a justification
in `files/vuln-ignore` (empty). It then writes a CycloneDX SBOM with the pinned
`cyclonedx-gomod` (`v1.12.0`).

## Operator steps (not in bashy CI)

```sh
# in a clone of github.com/qiangli/act_runner
git switch --orphan bashy-build
cp -R <bashy>/builds/act_runner/fork/. .
git add .github/workflows/bashy-build.yml bashy-build
git commit -m "bashy-build: act_runner v5.0.0 verified build"
git push -u origin bashy-build
git tag bashy-v5.0.0-1 && git push origin bashy-v5.0.0-1
```

Then repoint the yoke pin: `external/actrunner` resolves a `binmgr.URLSpec`
against `dl.gitea.com` today; it has to become the signed fork release above —
a `GitHubSpec` on `qiangli/act_runner`, verified against the signing identity
and issuer in the table at the top. That also moves it off the one yoke pin
with no signature to check. Whoever launches `cache-server` must pass the
shipped `act_runner-bashy.yaml` (or set `cache.host` itself); the binary bashy
ships does not hard-code it.
