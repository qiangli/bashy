# gitea — bashy verified build

bashy runs the git forge behind `bashy loom` (Gitea) only from a
**bashy-CI-built, keylessly Sigstore-signed build of the official upstream
release tag**. This directory is the declaration for that build. `fork/` is
installed as the `bashy-build` branch of `github.com/qiangli/gitea`; it carries
no upstream source — the workflow checks out the upstream tag fresh on every
run.

The tool is called **gitea** here because that is what it builds. **loom** is
yoke's name for the gitea-backed forge service that runs it
(`yoke/external/loom`, `pkg/fleet/baseline/services/loom.yaml`).

## Layout

Sources (edit these; `fork/` is GENERATED by `../render.sh gitea` and checked
by `../check.sh` — see `../README.md`):

```
tool.env                     the declaration: upstream repo/tag/commit, Go toolchain,
                             Node/pnpm, matrix, release assets (shipped verbatim as PIN)
build.yml                    TOOL-SPECIFIC build steps (see below); setup + audit come
                             from ../_shared/kinds/go
files/app.ini                no-tracking runtime baseline (shipped as gitea-bashy.ini)
files/otel.env               OpenTelemetry environment (disabled; local collector only)
files/no-tracking.env        proxy clearing + a pointer at the app.ini knobs
files/no-egress-test.sh      runtime gate: the built server makes no outbound connection
files/vuln-ignore            govulncheck waivers (one OSV id + justification; empty)
```

## Why gitea overrides the `go` kind's build

Gitea's release binaries carry the `bindata` build tag, which embeds the
templates, the public assets **and** the vite-built frontend. So the frontend
toolchain has to run before `go generate`, which the generic `go` kind knows
nothing about. `build.yml` therefore replaces the kind's build step with
upstream's own sequence at the pinned tag — `.github/actions/node-setup`,
`make deps-frontend` (`pnpm install --frozen-lockfile`), `make frontend`
(`pnpm exec vite build`), then `go generate -tags bindata ./...` and the build.
`setup.yml` and `audit.yml` still come from `../_shared/kinds/go`.

The lockfile is installed **frozen**, and a second step fails the build if
`pnpm-lock.yaml` came out modified anyway.

## Build configuration, and how it differs from upstream

Upstream's released binaries come from `tools/build-release.sh`:

| | upstream release | bashy build |
|---|---|---|
| `CGO_ENABLED` | `0` on every platform — "must disable CGO (host compiler & linker) to get host-independent static builds" | **same** |
| build tags | `bindata $TAGS`, with `TAGS` empty for a release | **same** (`bindata`) |
| `-trimpath` | not used | **added** |
| `-ldflags` | `-s -w -X main.Version=$(GITEA_VERSION) -X main.Tags=$(TAGS)`, where `GITEA_VERSION` is a `git describe` | `-s -w -buildid= -X main.Version=28.1.0 -X main.Tags=bindata` |
| platforms | linux (amd64, arm-5, arm-6, arm64, riscv64), windows (amd64, arm64), darwin (amd64, arm64), freebsd/amd64 | the four bashy ships: linux amd64/arm64, darwin amd64/arm64 (see `../README.md` §Windows legs) |

Two deliberate differences: the stamp comes from `PIN` instead of `git
describe`, so the build is reproducible; and `main.Tags` records `bindata`, the
tag set actually linked, rather than upstream's empty `TAGS` variable.

**sqlite needs no cgo at this tag.** `models/db/driver_sqlite_modernc.go` is
`//go:build !sqlite_mattn` — the pure-Go modernc driver is the default, and the
cgo `mattn` driver is behind an opt-in tag. A `CGO_ENABLED=0` binary therefore
supports `DB_TYPE = sqlite3`, which is what `files/app.ini` and yoke's loom use.

## No tracking: every knob at v28.1.0

Gitea is configured by `app.ini`, so the knobs live in the shipped
`files/app.ini` baseline (released as `gitea-bashy.ini`). It mirrors what
yoke's `external/loom` `renderConfig()` seeds, so a bashy-signed gitea and a
yoke-launched loom agree.

| Key | Section | Upstream default | bashy |
|---|---|---|---|
| `ENABLED` | `[cron.update_checker]` | `true` — **the one upstream phone-home**: a periodic DNS TXT lookup at `release.gitea.io` | `false` |
| `PROXY_ENABLED` | `[proxy]` | `false` | `false` (stated, not inherited) |
| `DISABLE_GRAVATAR` | `[picture]` | `false`, with `GRAVATAR_SOURCE = gravatar` — a third-party avatar request per user, on every page view | `true` |
| `ENABLE_FEDERATED_AVATAR` | `[picture]` | `false` | `false` (stated) |
| `DISABLE_SSH` | `[server]` | `false` | `true` (git over HTTP on loopback only) |
| `HTTP_ADDR` | `[server]` | `0.0.0.0` | `127.0.0.1` |
| `DISABLE_REGISTRATION` | `[service]` | `false` | `true` |
| `ENABLE_REVERSE_PROXY_*` | `[service]` | `false` | `false` (stated) |
| `ENABLED` | `[actions]` | `false` | `false`; the launcher turns it on when it also runs act_runner |
| `INSTALL_LOCK` | `[security]` | `false` (the `/install` screen) | `true` |
| `SECRET_KEY` | `[security]` | generated at install | `{{SECRET_KEY}}` — a **placeholder**; no key is ever baked into a release asset |

`files/no-tracking.env` clears `HTTP_PROXY`/`HTTPS_PROXY`/`ALL_PROXY` (Gitea's
outbound HTTP — migrations, webhooks, the update checker — honours them on top
of `[proxy]`) and pins `NO_PROXY` to loopback.

### OpenTelemetry

The shipped baseline configures no tracing. `files/otel.env` sets
`OTEL_SDK_DISABLED=true`, all three exporters to `none`, and pins the general
and per-signal endpoints at `http://127.0.0.1:31415` — byte-for-byte the
destinations yoke's `external/internal/serviceenv` `LocalOTLP()` installs, with
`OTEL_SERVICE_NAME=loom` to match. Standard SDK environment variables cannot
turn export on behind the operator's back.

### No-egress gate

`files/no-egress-test.sh` renders `app.ini` with a per-run `SECRET_KEY`, starts
the built binary bound to `127.0.0.1:13880`, probes `/api/healthz`,
`/api/v1/version`, `/`, `/explore/repos`, `/user/login` and
`/api/v1/settings/api` over loopback, idles 30 s past the startup cron window,
probes again and stops it.

- **Linux (authoritative):** a fresh network namespace (`sudo unshare --net`,
  only `lo`), the server traced with
  `strace -f -e trace=connect,sendto,sendmsg,sendmmsg` and run unprivileged via
  `setpriv`. Any AF_INET/AF_INET6 attempt other than loopback to its own port or
  to `127.0.0.1:31415` — including the update checker's DNS lookup, which the
  namespace makes fail but the trace still records — fails the build.
- **macOS:** `sandbox-exec` denies all `network-outbound` except
  `localhost:13880` and `localhost:31415`, and denies the mDNSResponder socket;
  any Sandbox deny for the process in the unified log fails the build.

## Audit

The `audit` job runs the pinned `govulncheck` (`v1.9.0`) in source mode over
`./...` and fails on any vulnerability that is **reachable** — one whose first
trace frame names a called function — unless it is listed with a justification
in `files/vuln-ignore` (empty today). It then writes a CycloneDX SBOM with the
pinned `cyclonedx-gomod` (`v1.12.0`).

The SBOM covers the Go module graph. Gitea's frontend dependencies are build-time
only (vite emits static assets; no npm package is shipped or executed at
runtime), and the frozen-lockfile gate is what pins them.

## Operator steps (not in bashy CI)

```sh
# in a clone of github.com/qiangli/gitea
git switch --orphan bashy-build
cp -R <bashy>/builds/gitea/fork/. .
git add .github/workflows/bashy-build.yml bashy-build
git commit -m "bashy-build: gitea v28.1.0 verified build"
git push -u origin bashy-build
git tag bashy-v28.1.0-1 && git push origin bashy-v28.1.0-1
```

Then repoint the yoke pin: `external/loom`'s `Spec()` resolves
`go-gitea/gitea` from GitHub today; it has to become the signed fork release
above, verified against the signing identity and issuer in the table at the top.
