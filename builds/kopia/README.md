# kopia — bashy verified build

bashy runs the snapshot-backup repository server behind `bashy kopia` (Kopia)
only from a **bashy-CI-built, keylessly Sigstore-signed build of the official
upstream release tag**. This directory is the declaration for that build.
`fork/` is installed as the `bashy-build` branch of `github.com/qiangli/kopia`;
it carries no upstream source — the workflow checks out the upstream tag fresh
on every run.

by `../check.sh` — see `../README.md`):


steps, and `verify-pin.sh`.

## Build configuration, and how it differs from upstream

Upstream splits its release across two paths: the linux archives come from
`.goreleaser.yml`, and the macOS/Windows archives from the `Makefile`'s
`KOPIA_BUILD_FLAGS` targets.

| | upstream release | bashy build |
|---|---|---|
| `CGO_ENABLED` | `0` for the linux archives (`.goreleaser.yml` `env`); the macOS archives are built natively on a mac runner with cgo left at its default (`1`) | **same** (`GO_CGO` in `tool.env`) |
| `-trimpath` | **already used** (`KOPIA_BUILD_FLAGS`, and `flags:` in `.goreleaser.yml`) | same |
| `-ldflags` | `-s -w -X repo.BuildVersion=$(KOPIA_VERSION_NO_PREFIX) -X repo.BuildInfo=$(shell git rev-parse HEAD) -X repo.BuildGitHubRepo=$(GITHUB_REPOSITORY)` | `-s -w -buildid=` + the same three, with `BuildInfo` taken from `PIN`'s `UPSTREAM_COMMIT` instead of a `git` call |
| platforms | linux/freebsd/openbsd × amd64/arm/arm64 (goreleaser), macOS amd64/arm64/universal, windows/amd64 | the four bashy ships: linux amd64/arm64, darwin amd64/arm64 (see `../README.md` §Windows legs) |

Upstream already does the reproducible-build work here, so the only
substantive change is `-buildid=` plus a stamp that reads the pinned commit
from `PIN` rather than from `git`. `BuildVersion` drops the leading `v`, as
upstream's `KOPIA_VERSION_NO_PREFIX` does.

**No separate web-UI fetch.** Kopia's server UI is a normal Go module
dependency at this tag (`github.com/kopia/htmluibuild` in `go.mod`), so it
arrives through `go.sum` like everything else — no second, unpinned upstream to
download, and the SBOM covers it.

## No tracking: every knob at v0.23.1

Kopia's one documented outbound call is its GitHub release check, and it is a
**flag**, not a configuration key, so the launcher must pass it on every
invocation. `files/no-tracking.env` states the policy; it is the same
`kopiaPrivacyArgs()` pair yoke's `external/kopia` launcher uses.

| Knob | Source | Upstream default | bashy |
|---|---|---|---|
| `--no-check-for-updates` | upstream flag reference, <https://kopia.io/docs/reference/command-line/flags/> | updates **are** checked (a periodic GitHub release query) | **passed on every invocation**, including `repository create` |
| `--otlp-trace` | same reference | off | **passed**; `otel.env` decides where the spans go |
| `--address` | `server start` | `127.0.0.1:51515` | `127.0.0.1:<port>` (stated) |
| `--insecure` / `--without-password` | `server start` | off | **on**: plain HTTP with no server-level auth, because the mesh is the boundary and the listener is loopback |

`files/no-tracking.env` also clears `HTTP_PROXY`/`HTTPS_PROXY`/`ALL_PROXY`
(Go's `net/http` honours them, so an operator shell could otherwise hand the
service an egress path) and pins `NO_PROXY` to loopback.

### OpenTelemetry

kopia is the one service in this set that **does** export. `--otlp-trace`
enables kopia's OTLP exporter through the standard SDK environment, so
`files/otel.env` leaves the SDK enabled and pins every destination at
`http://127.0.0.1:31415` — byte-for-byte the endpoints and protocols yoke's
`external/internal/serviceenv` `LocalOTLP()` installs. Metrics and logs have no
kopia exporter and are set to `none` rather than left to a default.

Because kopia legitimately dials the collector, the no-egress verdict tolerates
exactly two destinations: loopback to its own port, and `127.0.0.1:31415`.

### No-egress gate

`files/no-egress-test.sh` creates a filesystem repository and then starts the
built server bound to `127.0.0.1:15151` with `no-tracking.env` + `otel.env`,
probes `/`, `/api/v1/repo/status` and `/api/v1/sources` over loopback, idles
30 s, probes again and stops it. Both kopia invocations — `repository create`
and `server start` — run under the tracer, so the update check cannot hide in
the setup step.

- **Linux (authoritative):** a fresh network namespace (`sudo unshare --net`,
  only `lo`), traced with `strace -f -e
  trace=connect,sendto,sendmsg,sendmmsg` and run unprivileged via `setpriv`.
  Any AF_INET/AF_INET6 attempt other than loopback to its own port or to
  `127.0.0.1:31415` — including DNS and attempts the namespace makes fail — or
  a connect to a resolver socket fails the build.
- **macOS:** `sandbox-exec` denies all `network-outbound` except
  `localhost:15151` and `localhost:31415`, and denies the mDNSResponder socket;
  any Sandbox deny for the process in the unified log fails the build.

## Audit

The `audit` job runs the pinned `govulncheck` (`v1.9.0`) in source mode over
`./...` and fails on any vulnerability that is **reachable** — one whose first
trace frame names a called function — unless it is listed with a justification
in `files/vuln-ignore` (empty today). It then writes a CycloneDX SBOM with the
pinned `cyclonedx-gomod` (`v1.12.0`).

## Operator steps (not in bashy CI)

```sh
# in a clone of github.com/qiangli/kopia
git switch --orphan bashy-build
cp -R <bashy>/builds/kopia/fork/. .
git add .github/workflows/bashy-build.yml bashy-build
git commit -m "bashy-build: kopia v0.23.1 verified build"
git push -u origin bashy-build
git tag bashy-v0.23.1-1 && git push origin bashy-v0.23.1-1
```

Then repoint the yoke pin: `external/kopia`'s `Spec()` resolves `kopia/kopia`
from GitHub today (and `kopia.yaml` still says `version: v0.23.1`); it has to
become the signed fork release above, verified against the signing identity and
issuer in the table at the top.
