# klatch — bashy verified build

bashy runs the Klatch messaging server behind `bashy klatch` only from a
**bashy-CI-built, keylessly Sigstore-signed build**. This directory is the
declaration for that build. `fork/` is installed as the `bashy-build` branch
of `github.com/qiangli/klatch`; it carries no source of its own — the
workflow checks out the pinned commit fresh on every run.

| Toolchain | Go `1.26.9` (EOL-minor security override; the commit's `go.mod` names `go1.23.0`/`toolchain go1.24.5`, see #Build configuration) + Node `22` / Yarn `1.22.22` |

## Pin provenance: no upstream release tag

Every other tool in `builds/` names a **third-party** `UPSTREAM_SLUG` whose
own release the `pin` job queries for draft/pre-release status. Klatch has
no such upstream release to defer to: `balzack/databag` cuts no GitHub
releases at all, and `qiangli/klatch` — OUR fork, mid-rebrand — has not cut
one yet either. So `tool.env` points `UPSTREAM_REPO`/`UPSTREAM_SLUG` at the
**same** repo as `FORK_REPO` (`qiangli/klatch`): bashy plays both roles,
the pinned source and the build fork, rather than two different repos the
way every other tool's upstream/fork split works.

This changes nothing about the pipeline itself — `render.sh` and
`bashy-build.yml` are byte-identical to every other `official-release`
tool, and `verify-pin.sh`'s provenance gate (HEAD and the tag both resolve
to `UPSTREAM_COMMIT` over a pristine tree) is unchanged. It changes who
creates the tag the `pin` job queries: for every other tool that is a
third-party upstream maintainer; for Klatch it is bashy's own operator, on
bashy's own fork. The **one** field that pins this build is
`UPSTREAM_COMMIT` (`tool.env`); bumping to the eventual rebrand commit means
moving that field and cutting a matching `UPSTREAM_TAG` release to go with
it (same two edits any tool.env bump needs — see `../README.md` "Adding a
tool").

Operator step, once, before the pipeline can run at all (in addition to the
step every tool needs, below): in a clone of `qiangli/klatch`, tag commit
`45343338582b394f4f5fdb4b7e271ea1dc8dd5fd` as `v0.1.0` and cut a
**non-draft, non-prerelease** GitHub Release for it. That is the "upstream
release" the `pin` job's `official-release` admission queries — satisfied
here because bashy controls the fork, not because a third party published
it.

## Layout

Sources (edit these; `fork/` is GENERATED by `../render.sh klatch` and
checked by `../check.sh` — see `../README.md`):

```
tool.env                     the declaration: pinned commit, Go/Node toolchains,
                             matrix, release assets (shipped as PIN)
build.yml                    klatch's own setup+build (KIND=custom: one matrix
                             builds both the cgo Go server and the Node web bundle)
audit.yml                    govulncheck + yarn audit, both report-only (see #Audit)
files/otel.env               OpenTelemetry environment (disabled; local collector only)
files/no-tracking.env        proxy clearing; klatch has no tracking code of its own
files/no-egress-test.sh      runtime gate: the built server makes no outbound connection
```

Shared (`../_shared`): the workflow skeleton and `verify-pin.sh`. There is no
`builds/_shared/kinds/custom` — a `custom` kind always supplies its own
`setup`/`build`/`audit` fragments, same as `openclaw` and `ollama`.

## MVP scope

Linux `amd64`+`arm64` only, server binary + web bundle. Darwin and Windows
are deferred — the commit's `net/server` has no OS-specific code (`cgo`
needs only a C compiler, and GitHub ships native `ubuntu-24.04-arm`
runners, so this build cross-compiles nothing), but a macOS/Windows leg
needs its own no-egress gate shape and has not been written.

## Build configuration

Two unrelated artifacts from one `MATRIX`, which is why `KIND=custom`:
`build.yml` branches every step on `matrix.asset`, so the `klatch-web-*` leg
runs the Node/Yarn half and every other leg runs the Go half.

**Server** (`net/server`, upstream `Dockerfile`'s `go` stage):

| | upstream (`Dockerfile`) | bashy build |
|---|---|---|
| `CGO_ENABLED` | `1` (gorm's sqlite driver, `mattn/go-sqlite3`, needs a C compiler) | **same** |
| build command | `go build -o databag .` | `go build -trimpath -ldflags "-s -w -buildid=" -o klatch .` — same package, `-trimpath`/`-buildid=` dropped for a reproducible build, output renamed `klatch` |
| Go toolchain | `go.mod`: `go 1.23.0` / `toolchain go1.24.5`, both EOL minors (Go ships fixes for only its two newest) | **`1.26.9`**, an EOL-minor security override — see `../README.md` "Recorded security overrides" |
| platforms | whatever `DATABAG_GOOS`/`DATABAG_GOARCH` build args name | linux `amd64`+`arm64` only (#MVP scope) |

**Web** (`app/client/web`, upstream `Dockerfile`'s `node` stage):

| | upstream (`Dockerfile`) | bashy build |
|---|---|---|
| Node | `node:22-alpine` | **22** (`NODE_VERSION`, `actions/setup-node`) |
| install | `yarn --frozen-lockfile` | **same**, plus a reviewed `YARN_VERSION=1.22.22` pin (upstream pins neither) and a check that the lockfile was not rewritten |
| build | `yarn run build` (vite) | **same** |

## Release assets: two shapes

```
klatch-v0.1.0-linux-amd64.tar.gz   klatch binary + net/transform/*.sh
klatch-v0.1.0-linux-arm64.tar.gz   klatch binary + net/transform/*.sh
klatch-web-v0.1.0.tar.gz           the vite dist/ output (static, same for every arch)
klatch-v0.1.0.govulncheck.json     klatch-web-v0.1.0.yarn-audit.json
klatch-pin.txt                     klatch-otel.env
klatch-no-tracking.env             SHA256SUMS
```

The server tarball's binary is already executable when tarred, so
`RELEASE_EXECUTABLES` is empty — there is no raw executable asset to
`chmod +x` after the fact. Each asset gets a sibling `<asset>.sigstore.json`
bundle. URL shape:
`https://github.com/qiangli/klatch/releases/download/bashy-v0.1.0-1/<asset>`.

## No tracking

Reviewed at `net/server/go.mod`: klatch links no update checker, no
telemetry and no analytics dependency. Its only outbound-capable code is
`github.com/SherClockHolmes/webpush-go`, used to deliver browser push
notifications to an endpoint an **account** configures — a feature a user
opts into, not background telemetry, and the no-egress gate below never
exercises it (it needs a configured account and a real push endpoint).
`files/no-tracking.env` therefore only clears the proxy environment
(`HTTP_PROXY`/`HTTPS_PROXY`/`ALL_PROXY`; Go's `net/http` honours them, so an
operator shell could otherwise hand the service an egress path) and pins
`NO_PROXY` to loopback.

### OpenTelemetry

`net/server/go.mod` carries no `go.opentelemetry.io` module at all.
`files/otel.env` still sets `OTEL_SDK_DISABLED=true`, all three exporters to
`none`, and pins the general and per-signal endpoints at
`http://127.0.0.1:31415` — byte-for-byte the destinations yoke's
`external/internal/serviceenv` `LocalOTLP()` installs, so if a future pin
ever links an SDK, it can only reach bashy's own collector.

### No-egress gate

`files/no-egress-test.sh` branches on the asset it is given:

- **Web leg** (`klatch-web-*`): the tarball is static `vite` output with no
  executable code — nothing runs during this build, so there is nothing to
  trace. The gate extracts it and asserts it is a non-empty tree of plain,
  non-executable files.
- **Server legs**: extracts the tarball, starts `klatch` bound to
  `127.0.0.1:15000` with an empty sqlite store, probes `/admin/status`
  (`GetNodeStatus` — unauthenticated, answers from the store) for
  readiness, then `/account/status`, `/account/available` and `/` over
  loopback, idles 30 s, probes again and stops it. Linux only (#MVP scope):
  a fresh network namespace (`sudo unshare --net`, only `lo`), traced with
  `strace -f -e trace=connect,sendto,sendmsg,sendmmsg` and run unprivileged
  via `setpriv`. Any AF_INET/AF_INET6 attempt other than loopback to its own
  port or to `127.0.0.1:31415` — including DNS and attempts the namespace
  makes fail — fails the build.

## Audit

`govulncheck` (`v1.9.0`, source mode over `net/server`'s `./...`) and
`yarn audit` (`app/client/web`, frozen install) both run in the `audit` job
and both write a JSON report that ships as a release asset — but **neither
gates the release**: a reachable or unwaived finding is recorded, not
failed or waived. This is narrower than `builds/_shared/kinds/go`'s audit
(which fails the build on an unwaived reachable finding): Klatch is a fresh
rebrand with no accumulated `vuln-ignore`/`audit-exceptions` review yet, and
the sprint scope ("S518.4") calls for the reports to exist, not for that
review. Tightening this to a hard gate (matching every Go-kind tool) is
follow-up work once the first reports are read.

## Operator steps (not in bashy CI)

Once, before the first build (#Pin provenance): tag
`45343338582b394f4f5fdb4b7e271ea1dc8dd5fd` as `v0.1.0` on `qiangli/klatch`
and cut a non-draft, non-prerelease GitHub Release for it.

```sh
# in a clone of github.com/qiangli/klatch
git switch --orphan bashy-build
cp -R <bashy>/builds/klatch/fork/. .
git add .github/workflows/bashy-build.yml bashy-build
git commit -m "bashy-build: klatch v0.1.0 verified build"
git push -u origin bashy-build
git tag bashy-v0.1.0-1 && git push origin bashy-v0.1.0-1
```

Then wire the fleet to the signed fork release (outside this repo's
scope): a loopback-port assignment (7100/7101 — 7000 is Klatch's own
upstream default and already taken on the shared remote host) and the
signing identity/issuer above for verification.
