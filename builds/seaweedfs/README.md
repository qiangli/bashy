# seaweedfs — bashy verified build

bashy runs the S3-compatible object store behind `bashy seaweedfs` only from a
**bashy-CI-built, keylessly Sigstore-signed build of the official upstream
release tag**. This directory is the declaration for that build. `fork/` is
installed as the `bashy-build` branch of `github.com/qiangli/seaweedfs`; it
carries no upstream source — the workflow checks out the upstream tag fresh on
every run.

## The bare release-tag form

seaweedfs is the first tool in `builds/` whose upstream does **not** tag
`vMAJOR.MINOR.PATCH`. Its releases are bare `MAJOR.MINOR` — `4.48`, `4.47`,
`4.46` — and the last `v`-prefixed tag it ever cut is `v3.33`. The version is
not cosmetic: `weed/util/version/constants.go` names `MAJOR_VERSION = 4` and
`MINOR_VERSION = 48`, and formats `VERSION_NUMBER` as `4.48`.

`tool.env` therefore declares `UPSTREAM_TAG_FORM=X.Y`, which is the shape the
pin gate holds the tag to, in all three places that check it (the workflow's
`pin` job, the shipped `bashy-build/verify-pin.sh`, and `render.sh` itself).
The bashy release tag is `bashy-4.48-N` and the workflow trigger is
`bashy-[0-9]*`. Nothing about the form is sniffed from the pin — a typo in a
bumped tag is still refused. See `../README.md` §The declared release-tag form.

## Build configuration, and how it differs from upstream

Upstream publishes the plain `weed` binary from
`.github/workflows/binaries_release1.yml` (linux) and `binaries_release2.yml`
(darwin), both driving `wangyoucao577/go-release-action`:

| | upstream release | bashy build |
|---|---|---|
| `CGO_ENABLED` | `0` (`pre_command`) | **same** |
| `GODEBUG` | `http2client=0` (`pre_command`) | **same** (`GO_BUILD_ENV`) — see below |
| `-trimpath` | not used | **added** (reproducibility) |
| `-ldflags` | `-s -w -extldflags -static -X version.COMMIT=${{github.sha}}` | `-s -w -buildid= -X version.COMMIT=` **from `PIN`** |
| `-extldflags -static` | passed | **dropped** — it is an external-linker flag, and a `CGO_ENABLED=0` build does not invoke one |
| build tags | none for the plain asset | **same** (none) |
| platforms | linux/darwin/windows/freebsd/openbsd × amd64/arm/arm64, each also as `_large_disk` (`-tags 5BytesOffset`) and linux/amd64 as `_full` (`elastic,gocdk,rclone,sqlite,tarantool,tikv,ydb`) | the four bashy ships, plain variant only: linux amd64/arm64, darwin amd64/arm64 (see `../README.md` §Windows legs) |

`GODEBUG=http2client=0` is carried for fidelity with upstream's build
environment, not because it changes the artifact: a *shipped* godebug default
would have to come from a `godebug` line in `go.mod` or a `//go:debug`
directive, so exporting the variable around `go build` governs the build
process only. It is recorded here so nobody has to rediscover that.

The `large_disk` and `full` variants are deliberately not built: yoke runs the
plain `weed server`, and `5BytesOffset` changes the on-disk volume format.

## Security overrides: 17 reachable findings, 0 waivers

This pin is the worked example of `builds/README.md` §Recorded security
overrides, and it needs **both halves**. Nothing is waived — `files/vuln-ignore`
is empty, and reachable vulnerabilities are never waived.

**Toolchain half** — `GO_TOOLCHAIN_SECURITY_OVERRIDE=1.26.9`. 4.48's `go.mod`
has no `toolchain` line, so its directive is `go 1.26.6`, and govulncheck
reports **12 reachable stdlib vulnerabilities** in that release:
`GO-2026-6599`, `GO-2026-6600`, `GO-2026-6603`, `GO-2026-6605` and
`GO-2026-6607` … `GO-2026-6613`, `GO-2026-6617`. Every one is fixed in
`go1.26.9`, the newest patch of the tag's own Go minor. No later seaweedfs tag
exists, so the alternative to the override would be shipping those 12.

**Module half** — `GO_SECURITY_OVERRIDES="golang.org/x/net@v0.60.0"`. On
`go1.26.9`, **5 reachable findings remain**: `GO-2026-6603`, `GO-2026-6610`,
`GO-2026-6611`, `GO-2026-6612` and `GO-2026-6617`, all in
`golang.org/x/net`, which 4.48 requires at `v0.58.0`. All five are fixed in
`v0.60.0`. The workflow applies this with `go get` to the **same `src/` tree**
the audit and the build then use, and refuses any `go.mod` change outside that
module's require line — locally the whole diff is:

```
96c96
< 	golang.org/x/net v0.58.0
---
> 	golang.org/x/net v0.60.0
```

With both overrides applied, govulncheck reports **no reachable vulnerability**.
Three findings remain and are **module-level only** (no called-function trace
frame), which the gate treats as informational:
`GO-2022-0635` and `GO-2022-0646` in `github.com/aws/aws-sdk-go`, and
`GO-2026-5932` in `golang.org/x/crypto`.

Both overrides retire themselves the moment an upstream tag carries the fixes.

## No tracking: every knob at 4.48

seaweedfs is the **only tool in `builds/` whose tracking defaults to ON**, so
this table is the load-bearing part of the declaration. The collector posts
anonymous cluster statistics to `https://telemetry.seaweedfs.com/api/collect`
once 1 GiB is stored and then on an interval
(`weed/telemetry/collector.go:84`), which is why the control is the flag, not
an idle observation.

| Knob | Upstream source line | Upstream default | bashy |
|---|---|---|---|
| `-master.telemetry` (`weed server`) | `weed/command/server.go:113` | **`true`** | **`false`** |
| `-master.telemetry.url` (`weed server`) | `weed/command/server.go:112` | `https://telemetry.seaweedfs.com/api/collect` | unused once the flag is off |
| `-telemetry` (`weed master`) | `weed/command/master.go:115` | **`true`** | **`false`** |
| `-telemetry.url` (`weed master`) | `weed/command/master.go:114` | `https://telemetry.seaweedfs.com/api/collect` | unused once the flag is off |
| `-master.telemetry` (`weed mini`) | `weed/command/mini.go:442` | **`true`** | **`false`** |
| telemetry (`weed master_follower`) | `weed/command/master_follower.go:53` | already `false` | unchanged |
| `-ip`, `-ip.bind` | `weed/command/server.go:59-60` | `util.DetectedHostAddress()` / same as `-ip` | `127.0.0.1` — see below |

Whichever `weed` subcommand starts a master must carry the flag for that
subcommand: `weed server` and `weed mini` spell it `-master.telemetry=false`,
`weed master` spells it `-telemetry=false`. That is the whole contract, and
`files/no-egress-test.sh` is what proves it is honoured.

`-ip` is pinned to `127.0.0.1` as well. Its default is
`util.DetectedHostAddress()`, which enumerates interfaces and picks an
address — no outbound probe (unlike act_runner's cache server), but it would
make the four services address each other off-loopback.

`files/no-tracking.env` clears `HTTP_PROXY`/`HTTPS_PROXY`/`ALL_PROXY` (Go's
`net/http` honours them, so an operator shell could otherwise hand the service
an egress path) and pins `NO_PROXY` to loopback. The telemetry knobs are
**not** environment variables, so they cannot live there; the file points at
this table instead.

### OpenTelemetry

seaweedfs exposes Prometheus metrics on its own loopback port and links no
OpenTelemetry SDK at this tag — the `go.opentelemetry.io` modules in 4.48's
`go.mod` are all `// indirect`, pulled in by the gRPC and cloud-storage
dependencies, and no `weed/` package imports them. `files/otel.env` still sets
`OTEL_SDK_DISABLED=true`, all three exporters to `none`, and pins the general
and per-signal endpoints at `http://127.0.0.1:31415` — byte-for-byte the
destinations yoke's `external/internal/serviceenv` `LocalOTLP()` installs, so
if a future pin ever does export, it can only reach bashy's own collector.

### No-egress gate

`files/no-egress-test.sh` starts the built binary as a full `weed server`
stack — master, volume, filer and the S3 gateway — bound to `127.0.0.1` with
`-master.telemetry=false`, probes the S3 gateway, the master's
`/cluster/status` and `/dir/status` and the filer over loopback, idles 30 s,
probes again and stops it.

The four services talk to each other, so the allowed set is all of their
ports: the S3 gateway on `EGRESS_PORT` (default 15333), master/volume/filer on
the next three, each service's gRPC listener at its HTTP port + 10000
(`weed/pb/grpc_client_server.go:558`), and `127.0.0.1:31415`.

- **Linux (authoritative):** a fresh network namespace (`sudo unshare --net`,
  only `lo`), traced with `strace -f -e
  trace=connect,sendto,sendmsg,sendmmsg` and run unprivileged via `setpriv`.
  The verdict is the shared `egress-verdict.sh`: any AF_INET/AF_INET6 attempt
  other than loopback to one of those ports — including DNS and attempts the
  namespace makes fail — fails the build.
- **macOS:** `sandbox-exec` denies all `network-outbound` except those
  loopback ports, and denies the mDNSResponder socket; any Sandbox deny for
  the process in the unified log fails the build.

## Audit

The `audit` job runs the pinned `govulncheck` (`v1.9.0`) in source mode over
`./...`, **on the same overridden tree the build uses**, and fails on any
vulnerability that is reachable — one whose first trace frame names a called
function — unless it is listed with a justification in `files/vuln-ignore`
(empty). It then writes a CycloneDX SBOM with the pinned `cyclonedx-gomod`
(`v1.12.0`), so the SBOM records `golang.org/x/net v0.60.0` — what actually
shipped — rather than the tag's `v0.58.0`.

## Operator steps (not in bashy CI)

```sh
# in a clone of github.com/qiangli/seaweedfs
git switch --orphan bashy-build
cp -R <bashy>/builds/seaweedfs/fork/. .
git add .github/workflows/bashy-build.yml bashy-build
git commit -m "bashy-build: seaweedfs 4.48 verified build"
git push -u origin bashy-build
git tag bashy-4.48-1 && git push origin bashy-4.48-1
```

Then repoint the yoke pin: `external/seaweedfs`'s `Spec()` resolves
`seaweedfs/seaweedfs` from GitHub today with `DefaultVersion = "latest"`; it
has to become the signed fork release above, verified against the signing
identity and issuer in the table at the top, and pinned rather than `latest`.
Its `Start()` also needs `-master.telemetry=false` and `-ip=127.0.0.1` added to
the argv it launches — the binary bashy ships does not hard-code them, so the
launcher is where the knobs in §No tracking take effect.
