# victoria-logs — bashy verified build

bashy runs the log store behind its local OTel collector (VictoriaLogs) only
from a **bashy-CI-built, keylessly Sigstore-signed build of the official
upstream release tag**. This directory is the declaration for that build.
`fork/` is installed as the `bashy-build` branch of
`github.com/qiangli/victoria-logs`; it carries no upstream source — the
workflow checks out the upstream tag fresh on every run.

## Layout

Sources (edit these; `fork/` is GENERATED by `../render.sh victoria-logs` and
checked by `../check.sh` — see `../README.md`):

```
tool.env                     the declaration: upstream repo/tag/commit, Go toolchain,
                             build flags, matrix, release assets (shipped verbatim as PIN)
files/otel.env               OpenTelemetry environment (disabled; local collector only)
files/no-tracking.env        the flag policy a launcher must honour + proxy clearing
files/no-egress-test.sh      runtime gate: the built server makes no outbound connection
files/vuln-ignore            govulncheck waivers (one OSV id + justification; empty)
```

Shared (`../_shared`): the workflow skeleton, the `go` kind's setup/build/audit
steps, and `verify-pin.sh`.

## Build configuration, and how it differs from upstream

Upstream's released archives are produced by
`deployment/docker/Makefile`'s `app-via-docker-<goos>-<goarch>` targets over
`app-local-goos-goarch` in the root `Makefile`:

| | upstream release | bashy build |
|---|---|---|
| `CGO_ENABLED` | `1` on linux/amd64 and linux/arm64, `0` on darwin | **same** (`GO_CGO` in `tool.env`) |
| `-trimpath` | not used | **added** |
| `-ldflags` | `-X …/lib/buildinfo.Version=victoria-logs-$(DATEINFO_TAG)-$(BUILDINFO_TAG)` — a build **timestamp** plus `git describe` | `-s -w -buildid= -X …/lib/buildinfo.Version=victoria-logs-v1.51.0` |
| platforms | linux (amd64, arm64, arm, 386, ppc64le, s390x), darwin (amd64, arm64), freebsd, openbsd, windows/amd64 | the four bashy ships: linux amd64/arm64, darwin amd64/arm64 (see `../README.md` §Windows legs) |

The ldflags change is the point: upstream's stamp embeds the second the build
started, so two builds of the same tag can never match. Every value bashy
stamps comes from `PIN`, so re-running `bashy-v1.51.0-1` reproduces the bytes.
`-version` still reports a `vX.Y.Z` that `buildinfo.ShortVersion()` can parse.

## No tracking: every knob at v1.51.0

victoria-logs has **no update checker and no usage reporting**. Its outbound
surface is one flag, and the service is configured by flags, not environment
(upstream only reads `$VAR` for a flag when `-envflag.enable` is passed, which
bashy never passes).

| Knob | Source at the tag | Upstream default | bashy |
|---|---|---|---|
| `-httpListenAddr` | `app/victoria-logs/main.go` (`listenAddrs = []string{":9428"}` when unset) | `:9428` — **every interface** | `127.0.0.1:<port>` |
| `-pushmetrics.url` | `lib/pushmetrics/pushmetrics.go` | empty — no remote write | **never passed** |
| `-storageDataPath` | `app/vlstorage` | `victoria-logs-data` in `$PWD` | the service's own data dir |

`files/no-tracking.env` ships that policy next to the binary and additionally
clears `HTTP_PROXY`/`HTTPS_PROXY`/`ALL_PROXY` (Go's `net/http` honours them, so
an operator shell could otherwise hand the service an egress path) and pins
`NO_PROXY` to loopback.

### OpenTelemetry

victoria-logs is an OTLP **receiver** (`/insert/opentelemetry/v1/logs`), not an
exporter: the pinned release links no OpenTelemetry SDK. `files/otel.env` still
sets `OTEL_SDK_DISABLED=true`, all three exporters to `none`, and pins the
general and per-signal endpoints at `http://127.0.0.1:31415` — byte-for-byte
the destinations yoke's `external/internal/serviceenv` `LocalOTLP()` installs,
so if a future pin ever does export, it can only reach bashy's own collector.

### No-egress gate

`files/no-egress-test.sh` starts the built binary bound to `127.0.0.1:19428`
with `no-tracking.env` + `otel.env`, probes `/health`, `/metrics`,
`/select/logsql/query` and `/insert/jsonline` over loopback, idles 30 s, probes
again and stops it.

- **Linux (authoritative):** a fresh network namespace (`sudo unshare --net`,
  only `lo`), the server traced with
  `strace -f -e trace=connect,sendto,sendmsg,sendmmsg` and run unprivileged via
  `setpriv`. Any AF_INET/AF_INET6 attempt other than loopback to its own port or
  to `127.0.0.1:31415` — including DNS and attempts the namespace makes fail —
  or a connect to a resolver socket fails the build.
- **macOS:** `sandbox-exec` denies all `network-outbound` except
  `localhost:19428` and `localhost:31415`, and denies the mDNSResponder socket;
  any Sandbox deny for the process in the unified log fails the build.

## Audit

The `audit` job runs the pinned `govulncheck` (`v1.9.0`) in source mode over
`./...` and fails on any vulnerability that is **reachable** — one whose first
trace frame names a called function — unless it is listed with a justification
in `files/vuln-ignore` (empty today). It then writes a CycloneDX SBOM with the
pinned `cyclonedx-gomod` (`v1.12.0`).

## Operator steps (not in bashy CI)

```sh
# in a clone of github.com/qiangli/victoria-logs
git switch --orphan bashy-build
cp -R <bashy>/builds/victoria-logs/fork/. .
git add .github/workflows/bashy-build.yml bashy-build
git commit -m "bashy-build: victoria-logs v1.51.0 verified build"
git push -u origin bashy-build
git tag bashy-v1.51.0-1 && git push origin bashy-v1.51.0-1
```

Then repoint the yoke pin: `external/otel/stack/execstore.go`'s
`victoriaLogsSpec` resolves `VictoriaMetrics/VictoriaLogs` from GitHub today;
it has to become the signed fork release above, verified against the signing
identity and issuer in the table at the top.
