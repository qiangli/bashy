# Shape CLI and site MCP Contract (`CONTRACT.md`)

Behavioural specification for the `shape` surface (`bashy shape` plus the site MCP shaping tools). The pinned bashy reference is commit `bb467707bd5f0f7f269aab4e5ff9c188c7c00d23`. Assertions cover the local static-app workflow and refusal cases. Other service rules describe the surface and are tracked in [features.yaml](features.yaml).

## How assertions are judged

- Run the assertions in order in a disposable work directory with one fresh HOME and TMPDIR per run. S-01 through S-13 use an unregistered name. S-16 copies `examples/fixture/` into HOME, commits the fixture with fixed Git metadata, and registers it with `bashy app add` through a local file URL to preserve the baseline revision. It also prepares a separate workspace with an edited greeting. The fixture has a read-only smoke check and needs neither a shaping agent nor a running console.
- The lifecycle uses the synthetic principal `shape-tester`. For the scope commands the judge sets the local login and principal to `shape-owner`.
- Commands with `--json` and a JSON block are compared structurally. `"..."` matches any value, and `"...": "..."` allows additional object keys. An object without that marker is closed. `{ID}` binds the candidate ID and `{KEY}` binds its revision for the rest of the run.
- Plain text is checked where a console block gives it. The trailing `...` in refusal messages leaves the hint open. S-11 through S-13 assert exit codes only because the message can include the local HOME path.

## Output rules

- **Envelope.** The successful JSON responses asserted here are objects. Candidate and version objects are open. The diff is asserted as plain text (S-20).
- **Refusals.** Unregistered-app messages in S-01 through S-08 have a stable prefix and exit 1. S-09 and S-10 distinguish scope-name validation from app lookup.

## Definitions (input)

- An **app** is a name registered on the host (for example by `bashy app add --type shaped`). Lifecycle verbs take the app as their first operand. Scope verbs select it with `--app`. A name that is not registered is refused before any candidate work (S-01 to S-08).
- A **candidate** is an isolated revision generated by `wish` or imported with `wish --from`; it is identified by a candidate ID (`{ID}`). An import leaves the selected active revision in place until approval (S-18, S-23 through S-25).
- **Scope names** are exactly the set {`edit`, `shape`}: a scope name is valid when, lower-cased, it equals `edit` or `shape`, and invalid otherwise. Boundary pair: `bogus` is refused by the scope rule itself (S-09), while `edit` passes the scope rule and is then refused only because the app is not registered (S-10). `shape` includes `edit`. Audiences are circles AND (groups OR emails); an empty audience grants nothing.
- **Principals.** `--user` (alias `--principal`, or `BASHY_PRINCIPAL`) names the represented user; `--as` names the accountable caller; `--agent tool:model` names the generating agent. None of them overrides a remote console identity.
- The **wish request** is a plain-text request (see `examples/wish.txt`); the **scope grant** input is the flag form shown in `examples/scope-grant.txt`. No other input formats are part of this surface.

## Service rules

- `wish` generates a candidate in isolation; local `wish` waits for generation, and `wish --from WORKSPACE` copies a hand-made change without building in the supplied checkout.
- `verify` runs the trusted verifier on a candidate. Verification failure is a nonzero result with an inspectable verdict. `verify` does not call conform; conform evidence is produced only by `conform cert` and `conform mutate` (KI-4).
- `preview` shows a candidate in isolation: a URL on the paired console for a web app, the verified executable for a CLI-kind app, or a side-port URL for a service-kind app. S-22 asserts the candidate-specific URL returned for the static web app.
- `approve` re-verifies and then activates through the sealed activation gate. Only the owner approves. `reject` discards a candidate without activation.
- `undo` restores the previous version through the trusted gate; `restore` restores a named version through the same gate. S-27 through S-30 assert the resulting revision and the persisted active selection. S-12 and S-13 assert refusal on an unfetched app.
- `history` lists the selected principal's versions. `status` shows the active version and candidates; `show` inspects one candidate; `diff` shows its patch.
- **Site MCP.** The mounted site MCP registers exactly the shaping tools `shape_wish`, `shape_pull`, `shape_push`, `shape_verify`, `shape_preview`, `shape_approve` and `shape_undo`. Verified members with `shape` scope can wish, verify and preview; a wish from a member without that scope becomes a request on the owner's queue without running an agent. Approve and undo remain owner-only. There is no MCP tool that restores a named version (KI-3). Account strangers and anonymous visitors cannot shape or file requests.
- **Scope administration.** The local owner can persist a `shape` grant naming a circle. A separate `scope ls` reads the same grant (S-31, S-32).
- **Group shaping evidence.** The group loop above (member wish, owner approval, a second candidate from an old base refused naming both revisions, pull/edit/push with replay refusal) is proven only in a sandbox with a stub agent and synthetic accounts (KI-1). App data across a change and a restore is not asserted anywhere in this contract (KI-2).

### S-16
Register a static app from a private copy of the fixture and prepare an edited workspace.
```console
$ mkdir -p "$HOME/shape-fixture/public" "$HOME/shape-fixture/checks"
$ cp examples/fixture/public/index.html "$HOME/shape-fixture/public/"
$ cp examples/fixture/contract.bsh "$HOME/shape-fixture/"
$ cp examples/fixture/checks/smoke.bsh "$HOME/shape-fixture/checks/"
$ cp -R "$HOME/shape-fixture" "$HOME/shape-edit"
$ printf '%s\n' '<!doctype html>' '<title>Shape fixture</title>' '<h1 id="greeting">Shaped greeting</h1>' > "$HOME/shape-edit/public/index.html"
$ git -C "$HOME/shape-fixture" init -q --object-format=sha1
$ git -C "$HOME/shape-fixture" -c core.autocrlf=false add public/index.html contract.bsh checks/smoke.bsh
$ GIT_AUTHOR_DATE=2026-01-01T00:00:00Z GIT_COMMITTER_DATE=2026-01-01T00:00:00Z git -C "$HOME/shape-fixture" -c user.name='Shape Fixture' -c user.email=shape-fixture@example.invalid -c commit.gpgsign=false commit -qm 'Baseline greeting'
$ bashy app add shape-fixture --type shaped --source "file://$HOME/shape-fixture"
shape-fixture -> /shape-fixture/ (shaped, ...)
note: takes effect on the console's next request
```
exit: 0
