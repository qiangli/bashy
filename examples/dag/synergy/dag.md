# Agent ecosystem synergy — bounded fixture

One `dag.md` drives the whole S12 sequence through the **current Bashy CLI**:

    unpaired meet dm refusal → app pair approve → paired sender input
    → planner turn persisted into kb + todo → implementer turn
    → approve request → /approve from the paired sender → todo done + notify

What is real and what is a stand-in:

- **Real:** every control-plane command — `meet dm`, `app pair approve`,
  `app devices`, `meet list`, `meet contributions`, `kb note add`, `kb list`,
  `todo add/start/done/show`, `chat`, `approve request/show`, `notify`,
  `chat timeline`, `activity tail`. Nothing is mocked inside Bashy.
- **Stand-in (bounded):** the two external agent turns. Bashy launches the
  planner and implementer through its own agent launcher; the documented
  operator override `BASHY_TOOL_BINARY_CLAUDE` / `BASHY_TOOL_BINARY_CODEX`
  (`fleet.ToolBinaryOverrideEnv`) points that launcher at a deterministic
  script instead of the pinned CLI. The DAG never names the stub: unset the
  variables and the same file runs the live agents.
- **Stand-in (bounded):** messenger ingress. `bashy meet dm --channel C
  --sender S TEXT` *is* the gateway front door (a webhook relay feeds argv or
  stdin); here the relay is the DAG itself.

Every command's stdout, stderr and exit status land under `$STATE_DIR/raw/`
as `<step>.<command>.{out,err,status}`. `$STATE_DIR/event-ids.ndjson` has one
line per receipt. Its `event_id` is **only ever parsed from that receipt**
(`id_source` names the field/line); when the current CLI emits no ID the
line carries `"event_id": null` and an `absence` string that quotes exactly
what the receipt did carry. Nothing in this file invents an ID.

Every body starts with `set -euo pipefail`: the runner does not stop a body
at a failing line on its own, so each step is fail-closed by construction —
a refused pairing, a missing ID, an approval that did not reach `pending`, or
a `/approve` that did not land as `allow` fails the target and skips the rest.

This fixture is **not** evidence of the manager-owned live gates: the Linux
full-DAG run with real agents, real app pairing from a phone, and the
two-host approval remain separate checks (see `README.md`).

Scope defaults keep a host clean: the todo goes to the personal list
(`TODO_SCOPE=--user`) and the kb page to the host ring (`KB_RING=host`), so
running the fixture inside a repository never edits that repository's
committed `docs/todo/` or `docs/kb/`. Override both to write into a repo.

Re-running against the same `$HOME` after a completed pass refuses at the
first step (the sender is already paired). Revoke first:
`bashy meet dm --channel fixture --sender alice --revoke`.

## Tasks

### init

Fresh state directory plus the shared helper every later body sources.
`run_step` records a command's raw outcome before its status can fail the
body; `ledger` appends one receipt line; `need` fails closed on an empty ID.
Effects: read, write, exec

```bash
set -euo pipefail
test -n "$STATE_DIR"
RAW="$STATE_DIR/raw"
mkdir -p "$RAW"
: >"$STATE_DIR/event-ids.ndjson"
cat >"$STATE_DIR/lib.sh" <<'LIB'
# generated by examples/dag/synergy/dag.md (init) — sourced by every body
RAW="$STATE_DIR/raw"
LEDGER="$STATE_DIR/event-ids.ndjson"

# run_step NAME CMD... — run CMD, keep stdout/stderr/status under raw/NAME.*,
# then return CMD's status so `set -e` fails the body on a non-zero exit.
run_step() {
  local name=$1 st=0
  shift
  "$@" >"$RAW/$name.out" 2>"$RAW/$name.err" || st=$?
  printf '%s\n' "$st" >"$RAW/$name.status"
  if [ "$st" -ne 0 ]; then
    printf 'synergy: %s exited %s — see %s\n' "$name" "$st" "$RAW/$name.err" >&2
  fi
  return "$st"
}

# need VALUE WHAT — fail closed when a parsed value is empty.
need() {
  if [ -z "$1" ]; then
    printf 'synergy: %s\n' "$2" >&2
    return 1
  fi
}

# ledger STEP COMMAND ID_SOURCE EVENT_ID RECEIPT [ABSENCE]
# EVENT_ID empty → "event_id": null plus the mandatory ABSENCE text.
ledger() {
  local step=$1 cmd=$2 src=$3 id=$4 receipt=$5 absence=${6-}
  local st
  st=$(<"$RAW/$receipt.status")
  if [ -n "$id" ]; then
    printf '{"step":"%s","command":"%s","exit":%s,"id_source":"%s","event_id":"%s","receipt":"raw/%s.out"}\n' \
      "$step" "$cmd" "$st" "$src" "$id" "$receipt" >>"$LEDGER"
  else
    need "$absence" "ledger: a null event_id needs the exact absence text"
    printf '{"step":"%s","command":"%s","exit":%s,"id_source":"%s","event_id":null,"absence":"%s","receipt":"raw/%s.out"}\n' \
      "$step" "$cmd" "$st" "$src" "$absence" "$receipt" >>"$LEDGER"
  fi
}

# slug STRING — the room-name form meet uses for an identity ([^A-Za-z0-9] → -).
slug() {
  local s=$1
  printf '%s' "${s//[^A-Za-z0-9]/-}"
}
LIB
. "$STATE_DIR/lib.sh"
run_step init.version "$BASHY" --version
printf 'planner=%s implementer=%s channel=%s sender=%s task=%s\n' \
  "$PLANNER" "$IMPLEMENTER" "$CHANNEL" "$SENDER" "$TASK" >"$STATE_DIR/params"
```

### unpaired-refusal

The external sender is unknown: `meet dm` mints a single-use pair code and
invokes **no** agent. The code is the only ID this step produces, parsed
from the refusal line itself.
Requires: init
Effects: read, write, exec, net, persist, spend

```bash
set -euo pipefail
. "$STATE_DIR/lib.sh"
run_step unpaired.meet-dm "$BASHY" meet dm "$PLANNER" --channel "$CHANNEL" --sender "$SENDER" "plan $TASK"
reply=$(<"$RAW/unpaired.meet-dm.out")
case $reply in
  *"message not delivered"*) ;;
  *) need "" "unpaired-refusal: sender $SENDER on $CHANNEL was not refused (already paired? revoke with: $BASHY meet dm --channel $CHANNEL --sender $SENDER --revoke): $reply" ;;
esac
PAIR_CODE=
if [[ $reply =~ pair\ code\ ([A-Z0-9-]+) ]]; then PAIR_CODE=${BASH_REMATCH[1]}; fi
need "$PAIR_CODE" "unpaired-refusal: no 'pair code' in the refusal (a pending ticket from an earlier run? deny or revoke it first): $reply"
printf '%s\n' "$PAIR_CODE" >"$STATE_DIR/pair-code"
ledger unpaired-refusal "meet dm" "meet dm stdout: 'pair code <CODE>'" "$PAIR_CODE" unpaired.meet-dm
```

### pair-approve

The operator redeems the code into a device bound to exactly this
(channel, sender) with the `ask` and `approve` scopes. The device ID comes
from the approve receipt and is cross-checked against `app devices --json`.
Requires: unpaired-refusal
Effects: read, write, exec, net, persist

```bash
set -euo pipefail
. "$STATE_DIR/lib.sh"
PAIR_CODE=$(<"$STATE_DIR/pair-code")
run_step pair.app-pair-approve "$BASHY" app pair approve "$PAIR_CODE" --allow ask,approve
receipt=$(<"$RAW/pair.app-pair-approve.out")
DEVICE_ID=
if [[ $receipt =~ paired\ .*\ as\ ([A-Za-z0-9_-]+) ]]; then DEVICE_ID=${BASH_REMATCH[1]}; fi
need "$DEVICE_ID" "pair-approve: no device id in the approve receipt: $receipt"
run_step pair.app-devices "$BASHY" app devices --json
devices=$(<"$RAW/pair.app-devices.out")
case $devices in
  *"\"id\": \"$DEVICE_ID\""*|*"\"id\":\"$DEVICE_ID\""*) ;;
  *) need "" "pair-approve: device $DEVICE_ID is not listed by app devices --json" ;;
esac
printf '%s\n' "$DEVICE_ID" >"$STATE_DIR/device-id"
ledger pair-approve "app pair approve" "app pair approve stdout: 'paired ... as <ID>'" "$DEVICE_ID" pair.app-pair-approve
ledger pair-approve "app devices" "app devices --json: .[].id" "$DEVICE_ID" pair.app-devices
```

### paired-input

The same message, now from a paired sender, reaches the planner: Bashy
launches it through its agent launcher and relays the reply on stdout. The
durable DM room this created is the step's ID, read from `meet list`, and
its transcript is kept through `meet contributions`.
Requires: pair-approve
Effects: read, write, exec, net, persist, spend

```bash
set -euo pipefail
. "$STATE_DIR/lib.sh"
run_step paired.meet-dm "$BASHY" meet dm "$PLANNER" --channel "$CHANNEL" --sender "$SENDER" \
  "Plan $TASK: the implementer must create $EXPECTED_PATH in this working directory with exactly $EXPECTED_CONTENT followed by one newline."
reply=$(<"$RAW/paired.meet-dm.out")
case $reply in
  *"message not delivered"*|*"is not paired for"*|"(agent returned no text)"*|"")
    need "" "paired-input: the paired message did not produce an agent reply: $reply" ;;
esac
run_step paired.meet-list "$BASHY" meet list
suffix="$(slug "$CHANNEL")-$(slug "$SENDER")"
ROOM_ID=
while read -r _room name id _rest; do
  case $name in
    dm-*-"$suffix") ROOM_ID=$id ;;
  esac
done <"$RAW/paired.meet-list.out"
need "$ROOM_ID" "paired-input: meet list shows no dm-*-$suffix room"
run_step paired.meet-contributions "$BASHY" meet contributions "$ROOM_ID" --json
transcript=$(<"$RAW/paired.meet-contributions.out")
case $transcript in
  *"\"speaker\": \"$CHANNEL:$SENDER\""*) ;;
  *) need "" "paired-input: the DM transcript has no contribution from $CHANNEL:$SENDER" ;;
esac
printf '%s\n' "$ROOM_ID" >"$STATE_DIR/room-id"
ledger paired-input "meet dm" "meet dm stdout is the agent reply; no id on it" "" paired.meet-dm "meet dm prints the relayed reply only; the room id is read from meet list"
ledger paired-input "meet list" "meet list ID column of the dm-*-$suffix row" "$ROOM_ID" paired.meet-list
```

### claude-plan

The planner's reply is the plan. Bashy persists it as a candidate kb page
and opens exactly one todo; both IDs come back on the receipts and are the
only IDs handed downstream — nothing is selected from a list.
Requires: paired-input
Effects: read, write, exec

```bash
set -euo pipefail
. "$STATE_DIR/lib.sh"
run_step plan.kb-note-add "$BASHY" kb note add --ring "$KB_RING" --candidate --type decision \
  --title "Plan: $TASK" --description "planner reply relayed by meet dm for $TASK" \
  --file "$RAW/paired.meet-dm.out"
added=$(<"$RAW/plan.kb-note-add.out")
KB_SLUG=
if [[ $added =~ added\ note\ ([a-z0-9-]+) ]]; then KB_SLUG=${BASH_REMATCH[1]}; fi
need "$KB_SLUG" "claude-plan: kb note add printed no 'added note <slug>': $added"
run_step plan.kb-list "$BASHY" kb list --ring "$KB_RING" --json
pages=$(<"$RAW/plan.kb-list.out")
KB_ID=
if [[ $pages =~ \"slug\":[[:space:]]*\"$KB_SLUG\",[[:space:]]*\"ref\":[[:space:]]*\"[^\"]*\",[[:space:]]*\"id\":[[:space:]]*\"([^\"]+)\" ]]; then KB_ID=${BASH_REMATCH[1]}; fi
need "$KB_ID" "claude-plan: kb list --json has no id for slug $KB_SLUG"
run_step plan.todo-add "$BASHY" todo add "Implement $TASK" $TODO_SCOPE --kind feature \
  --note "plan: kb:$KB_SLUG — implementer: $IMPLEMENTER — raised by $CHANNEL:$SENDER" --json
todo=$(<"$RAW/plan.todo-add.out")
TODO_ID=
if [[ $todo =~ \"id\":[[:space:]]*\"([0-9a-f]+)\" ]]; then TODO_ID=${BASH_REMATCH[1]}; fi
need "$TODO_ID" "claude-plan: todo add --json returned no id: $todo"
printf '%s\n' "$KB_SLUG" >"$STATE_DIR/kb-slug"
printf '%s\n' "$KB_ID" >"$STATE_DIR/kb-id"
printf '%s\n' "$TODO_ID" >"$STATE_DIR/todo-id"
ledger claude-plan "kb note add" "kb note add stdout: 'added note <slug>'" "$KB_SLUG" plan.kb-note-add
ledger claude-plan "kb list" "kb list --json: .pages[slug].id" "$KB_ID" plan.kb-list
ledger claude-plan "todo add" "todo add --json: .id" "$TODO_ID" plan.todo-add
```

### codex-implementation

The implementer runs as a real one-shot agent turn through `bashy chat`,
addressed with the exact todo and kb page created above. Its
`bashy-chat-v1` envelope carries no turn ID; the ledger says so instead of
inventing one.
Requires: claude-plan
Effects: read, write, exec, net, spend

```bash
set -euo pipefail
. "$STATE_DIR/lib.sh"
TODO_ID=$(<"$STATE_DIR/todo-id")
KB_SLUG=$(<"$STATE_DIR/kb-slug")
run_step impl.todo-start "$BASHY" todo start "$TODO_ID" $TODO_SCOPE
started=$(<"$RAW/impl.todo-start.out")
STARTED_ID=
if [[ $started =~ ^doing\ ([0-9a-f]+) ]]; then STARTED_ID=${BASH_REMATCH[1]}; fi
case $STARTED_ID in
  "") need "" "codex-implementation: todo start did not report .doing <id>.: $started" ;;
  "${TODO_ID:0:${#STARTED_ID}}") ;;
  *) need "" "codex-implementation: todo start acted on $STARTED_ID, not the created todo $TODO_ID" ;;
esac
run_step impl.chat "$BASHY" chat --agent "$IMPLEMENTER" --json \
  --task "implement todo:$TODO_ID" \
  -m "Implement todo:$TODO_ID ($TASK) following plan kb:$KB_SLUG. Create $EXPECTED_PATH in this working directory with exactly $EXPECTED_CONTENT followed by one newline. Reply with what you changed."
envelope=$(<"$RAW/impl.chat.out")
case $envelope in
  *'"schema_version":"bashy-chat-v1"'*) ;;
  *) need "" "codex-implementation: chat --json returned no bashy-chat-v1 envelope: $envelope" ;;
esac
case $envelope in
  *'"exit_code":0'*) ;;
  *) need "" "codex-implementation: the implementer turn did not exit 0: $envelope" ;;
esac
if [[ $envelope =~ \"output\":\"\" ]]; then need "" "codex-implementation: the implementer returned no output"; fi
need "$EXPECTED_PATH" "codex-implementation: EXPECTED_PATH is empty"
if [ ! -f "$EXPECTED_PATH" ]; then
  need "" "codex-implementation: implementer returned text but did not create $EXPECTED_PATH"
fi
printf '%s\n' "$EXPECTED_CONTENT" >"$STATE_DIR/expected-artifact"
run_step impl.artifact-verify cmp "$STATE_DIR/expected-artifact" "$EXPECTED_PATH"
ledger codex-implementation "todo start" "todo start stdout: 'doing <id-prefix> — <title>' (prefix of todo add .id)" "$STARTED_ID" impl.todo-start
ledger codex-implementation "chat" "bashy-chat-v1 envelope" "" impl.chat "bashy-chat-v1 carries agent, nick, model, cwd, args, exit_code and output but no turn or session id"
```

### approval-request

Completing the todo is the gated operation: the approval is raised on the
shared queue and must be `pending` before anything continues. No exit
status is swallowed: a request that does not land fails the target.
Requires: codex-implementation
Effects: read, write, exec, priv

```bash
set -euo pipefail
. "$STATE_DIR/lib.sh"
TODO_ID=$(<"$STATE_DIR/todo-id")
run_step approval.approve-request "$BASHY" approve request --json --source confirm \
  -- bashy todo done "$TODO_ID"
request=$(<"$RAW/approval.approve-request.out")
APPROVAL_ID=
if [[ $request =~ \"id\":[[:space:]]*\"([0-9a-f]+)\" ]]; then APPROVAL_ID=${BASH_REMATCH[1]}; fi
need "$APPROVAL_ID" "approval-request: approve request --json returned no id: $request"
case $request in
  *'"state":"pending"'*) ;;
  *) need "" "approval-request: the request is not pending: $request" ;;
esac
TOKEN=
if [[ $request =~ \"token\":[[:space:]]*\"([0-9a-f]+)\" ]]; then TOKEN=${BASH_REMATCH[1]}; fi
need "$TOKEN" "approval-request: approve request --json returned no token: $request"
printf '%s\n' "$APPROVAL_ID" >"$STATE_DIR/approval-id"
printf '%s\n' "$TOKEN" >"$STATE_DIR/approval-token"
ledger approval-request "approve request" "approve request --json: .id (token .token=$TOKEN)" "$APPROVAL_ID" approval.approve-request
```

### approve

The paired sender settles the queue through the messenger `/approve`
command — the `approve` scope granted at pairing — and no agent decides for
itself. The decision is read back with `approve show` and must be `allow`
by exactly `channel:sender`.
Requires: approval-request
Effects: read, write, exec, net, persist, spend, priv

```bash
set -euo pipefail
. "$STATE_DIR/lib.sh"
APPROVAL_ID=$(<"$STATE_DIR/approval-id")
run_step approve.meet-dm "$BASHY" meet dm "$PLANNER" --channel "$CHANNEL" --sender "$SENDER" "/approve $APPROVAL_ID"
verdict=$(<"$RAW/approve.meet-dm.out")
ALLOWED_ID=
if [[ $verdict =~ ^allow\ ([0-9a-f]+) ]]; then ALLOWED_ID=${BASH_REMATCH[1]}; fi
need "$ALLOWED_ID" "approve: /approve did not answer 'allow <id>': $verdict"
if [ "$ALLOWED_ID" != "$APPROVAL_ID" ]; then
  need "" "approve: /approve settled $ALLOWED_ID, not the requested $APPROVAL_ID"
fi
run_step approve.approve-show "$BASHY" approve show "$APPROVAL_ID" --json
shown=$(<"$RAW/approve.approve-show.out")
case $shown in
  *'"state":"allow"'*) ;;
  *) need "" "approve: approve show does not report state allow: $shown" ;;
esac
case $shown in
  *"\"by\":\"$CHANNEL:$SENDER\""*) ;;
  *) need "" "approve: the decision was not recorded as by $CHANNEL:$SENDER: $shown" ;;
esac
ledger approve "meet dm /approve" "meet dm stdout: 'allow <id> (...)'" "$ALLOWED_ID" approve.meet-dm
ledger approve "approve show" "approve show --json: .id with .decision.by=$CHANNEL:$SENDER" "$APPROVAL_ID" approve.approve-show
```

### done-notification

The approved operation runs, the sender is notified, and the host event log
is read back. The `bashy-bus-v1` receipt and the timeline lines carry no IDs
and the activity journal has no producer wired in this binary; each absence
is recorded as such.
Requires: approve
Effects: read, write, exec, net, persist, spend, priv

```bash
set -euo pipefail
. "$STATE_DIR/lib.sh"
TODO_ID=$(<"$STATE_DIR/todo-id")
APPROVAL_ID=$(<"$STATE_DIR/approval-id")
run_step done.todo-done "$BASHY" todo done "$TODO_ID" $TODO_SCOPE
finished=$(<"$RAW/done.todo-done.out")
DONE_ID=
if [[ $finished =~ ^done\ ([0-9a-f]+) ]]; then DONE_ID=${BASH_REMATCH[1]}; fi
case $DONE_ID in
  "") need "" "done-notification: todo done did not report .done <id>.: $finished" ;;
  "${TODO_ID:0:${#DONE_ID}}") ;;
  *) need "" "done-notification: todo done acted on $DONE_ID, not the created todo $TODO_ID" ;;
esac
run_step done.todo-show "$BASHY" todo show "$TODO_ID" $TODO_SCOPE --json
shown=$(<"$RAW/done.todo-show.out")
case $shown in
  *'"status": "done"'*|*'"status":"done"'*) ;;
  *) need "" "done-notification: todo $TODO_ID is not done: $shown" ;;
esac
# The notification is authored by the implementer seat. bashy notify refuses
# an anonymous sender, so the seat is claimed here unless the invoking
# session already carries an identity (a live run does).
NOTIFY_AS=${NOTIFY_AS:-$IMPLEMENTER}
export BASHY_AGENT="${BASHY_AGENT:-$NOTIFY_AS}" BASHY_PRINCIPAL="${BASHY_PRINCIPAL:-$NOTIFY_AS}"
run_step done.notify "$BASHY" notify --to "$CHANNEL:$SENDER" \
  "$TASK implemented; approval $APPROVAL_ID allowed; todo $TODO_ID done" --json
receipt=$(<"$RAW/done.notify.out")
NOTIFY_STATE=
if [[ $receipt =~ \"state\":[[:space:]]*\"([a-z]+)\" ]]; then NOTIFY_STATE=${BASH_REMATCH[1]}; fi
need "$NOTIFY_STATE" "done-notification: notify --json returned no state: $receipt"
if [ "$NOTIFY_STATE" = failed ]; then need "" "done-notification: notify failed: $receipt"; fi
run_step done.chat-timeline "$BASHY" chat timeline -n 40
timeline=$(<"$RAW/done.chat-timeline.out")
case $timeline in
  *"approval:${APPROVAL_ID:0:8}"*) ;;
  *) need "" "done-notification: the host event log has no approval:${APPROVAL_ID:0:8} event" ;;
esac
case $timeline in
  *"todo:${TODO_ID:0:8}"*) ;;
  *) need "" "done-notification: the host event log has no todo:${TODO_ID:0:8} event" ;;
esac
run_step done.activity-tail "$BASHY" activity tail 40
ledger done-notification "todo done" "todo done stdout: 'done <id-prefix> — <title>' (prefix of todo add .id)" "$DONE_ID" done.todo-done
ledger done-notification "notify" "bashy-bus-v1 receipt .state=$NOTIFY_STATE" "" done.notify "bashy-bus-v1 carries schema_version, state, principal, to and subject but no id"
ledger done-notification "chat timeline" "host event log lines (type actor target body)" "" done.chat-timeline "chat timeline renders the room timeline without an id column and has no --json; bashy events is not mounted in this binary"
ledger done-notification "activity tail" "bashy-activity-v1 journal" "" done.activity-tail "activity tail prints no records here: the journal lists its sources but no producer writes to it in this binary"
printf 'synergy: done — ledger %s\n' "$STATE_DIR/event-ids.ndjson"
```
