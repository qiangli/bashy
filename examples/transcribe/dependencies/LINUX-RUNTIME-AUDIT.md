# S503.6 Linux Whisper static runtime evidence

Story #2742, Story-ID `74ed924ba244`.

`-static-libgcc -static-libstdc++` selects a link policy; it does not show
which object files entered `whisper-cli`. `ldd` reports dynamic libraries only.
The Linux native build now retains the GNU-style final linker map as
`evidence/whisper-cli.link.map` and a parsed
`evidence/whisper-link-inventory.json`. The build report binds both to the
finished executable SHA-256 and the one verbose `whisper-cli` link command.
The parser caps the raw map at 32 MiB and the verbose log at 16 MiB. Missing,
oversized, malformed, or unreconciled map evidence fails the build recipe.
Windows keeps its separate PE map parser and evidence schema.

For each archive member, `archive_members` records the archive path, member
name, and whether an output section names that member. The GNU ld inclusion
table establishes that the linker selected a member; an output section gives
stronger evidence that its bytes remain in the binary. `direct_objects` lists
objects outside archives. `runtime_archive_members` filters selected
`libstdc++.a`, `libsupc++.a`, and `libgcc*.a` members. An empty list means the
map did not show those members, **not** that the binary has an admitted
license. The raw map and executable must be retained together for review.
The dynamic import gate also rejects `libstdc++.so*` and `libgcc_s.so*`.

To inspect one native artifact, rehash the binary and map against
`build-report.json`, then inspect `link_map_inventory.runtime_archive_members`
and their `in_output_section` values. Compare the full raw map inclusion table
and input-section rows to the JSON; resolve each archive path to the exact
native GCC package and source tree. The six-target CI workflow performs the
byte and schema checks but does not classify license compliance.

## Notices and decisions still needed

- For each selected GCC runtime object, identify the exact GCC version,
  distribution package, corresponding source file, copyright holder, and
  license header. Collect the matching `COPYING3`, `COPYING.RUNTIME`, and
  source-specific notices from that package. The inventory's
  `GPL-3.0-or-later WITH GCC-exception-3.1` label is a **candidate**, not an
  automated finding for every file. [The FSF exception text](https://www.gnu.org/licenses/gcc-exception-3.1.en.html)
  applies only to files carrying the applicable notice.
- Determine whether every object was generated by an eligible compilation
  process and whether the linked Whisper components are independent modules
  under that exception. Check any mixed compiler or prebuilt object path
  against the [FSF rationale and FAQ](https://www.gnu.org/licenses/gcc-exception-3.1-faq.html.en).
  Record the reviewer and the exact package/source evidence for the ruling.
- Decide whether distributing a binary containing those runtime objects is
  consistent with this repository's permissive-only linked-code policy, even
  if the exception permits distribution under other terms. If not, choose a
  different dependency build or distribution path. Keep any required copyright,
  GPL, and exception notices in the eventual package.
- Review every `unclassified_archives` entry and any direct object whose source
  is outside the pinned Whisper tree. A map is an object inventory, not a
  source-license scanner. Dynamic glibc and OS library terms, release SBOM,
  vulnerability review, signatures, and operator-host installation remain
  separate gates.

No Linux product dependency is admitted by this evidence capture or by a
successful native source build alone.
