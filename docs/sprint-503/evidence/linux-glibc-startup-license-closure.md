# S503.6 Ubuntu glibc startup-object license review

**Decision: retain `product_admitted=false` for both Linux targets.** The [native run 40216444004 receipt](linux-shared-gcc-40216444004/review.json) identifies `Scrt1.o`, `crti.o`, and `crtn.o` from `libc6-dev` **2.39-0ubuntu8.9** on Ubuntu 24.04 amd64 and arm64. It records their runner paths and SHA-256 values and verifies the two executable attestations. The objects themselves were not retained for an independent byte comparison. This review maps the recorded package version to source and license text; it does not establish which sections survived the final executable link.

## Exact source mapping

I downloaded Ubuntu's [2.39-0ubuntu8.9 source declaration](https://archive.ubuntu.com/ubuntu/pool/main/g/glibc/glibc_2.39-0ubuntu8.9.dsc), [glibc 2.39 source archive](https://archive.ubuntu.com/ubuntu/pool/main/g/glibc/glibc_2.39.orig.tar.xz), and [Ubuntu patch archive](https://archive.ubuntu.com/ubuntu/pool/main/g/glibc/glibc_2.39-0ubuntu8.9.debian.tar.xz). The two archives matched the declaration's SHA-256 values `f77bd47cf8170c57365ae7bf86696c118adb3b120d3259c64c502d3dc1e2d926` and `d6114f2302896a3c8612453e1bf1d0e61603e3029ba4a7c246fbb1ab4c48d2b0`. A search of the Ubuntu patch archive found no patch touching the source files or `csu/Makefile` listed below. The declaration's signature was not verified in this review.

The [glibc 2.39 `Makeconfig`](https://sourceware.org/git/gitweb.cgi?p=glibc.git;a=blob_plain;f=Makeconfig;hb=glibc-2.39) sets `start-installed-name = crt1.o`. The [`csu/Makefile`](https://sourceware.org/git/gitweb.cgi?p=glibc.git;a=blob_plain;f=csu/Makefile;hb=glibc-2.39) builds its `S` variant from `start.os`, `abi-note.o`, and `init.o` with a relocatable link, and installs `crti.o` and `crtn.o`. **Inference from those build rules and the architecture source layout:** `Scrt1.o` contains code/data from all three named inputs, with the architecture-specific `start.S` selected in place of generic `csu/start.c`. The receipt's direct linker inputs match those output names on both runners.

The exception is in the named files, **not** a blanket glibc startup-object exception. It preserves LGPL restrictions for modification of those files and their distribution outside a linked program. `csu/init.c` defines `_IO_stdin_used`; its inclusion in `Scrt1.o` is why the object cannot be marked exception-only from the source headers. The [LGPL 2.1 text](https://www.gnu.org/licenses/old-licenses/lgpl-2.1.html) §6 and [GNU's static-versus-dynamic linking FAQ](https://www.gnu.org/licenses/gpl-faq.html#LGPLStaticVsDynamic) are the relevant primary guidance for an executable containing non-exempt library code. **Inference requiring a legal/product decision:** if `init.c` bytes survive in the distributed executable, meeting the LGPL conditions may require a notice, the applicable library source, and a way for recipients to relink a modified library component, even though the rest of glibc is dynamically loaded. The retained receipts do not prove the byte-survival or a complete compliance bundle.

GCC's `crtbeginS.o` and `crtendS.o` are a **separate** issue: the preceding [shared-GCC receipt](linux-shared-gcc-40215118171/review.json) records them from `libgcc-13-dev` 13.3.0-6ubuntu2~24.04.1. GCC's [13.3 `libgcc/crtstuff.c`](https://gcc.gnu.org/git/?p=gcc.git;a=blob_plain;f=libgcc/crtstuff.c;hb=releases/gcc-13.3.0) bears GPL-3-or-later with the [GCC Runtime Library Exception 3.1](https://www.gnu.org/licenses/gcc-exception-3.1.html). That exception can permit distribution of target code formed through an eligible compilation process; it does **not** grant an exception to glibc's `csu/init.c`. Mapping the Ubuntu GCC package build and confirming eligibility remain separate review work, as do host-provided GCC shared runtime and ABI policy.

## Product decision options

1. **Accept an LGPL compliance path:** obtain product/legal review of `init.c` and the exact linked bytes, then prepare the required notices, source and relink materials under LGPL 2.1 §6 before distributing these binaries.
2. **Remove the non-exempt input:** change the startup link to omit or replace `init.o` using a reviewed source and ABI strategy; rebuild natively, retain the link map and object/section evidence, and rerun license and behavior gates.
3. **Choose another Linux toolchain/runtime:** re-establish source, license, ABI and native evidence for both architectures. A toolchain change alone does not preserve the current receipts.

None of these options is selected by this evidence. The existing two-target experiment remains unadmitted; ABI floors, GCC runtime policy, notice packaging, and the full six-target transcription/video gates remain open.
