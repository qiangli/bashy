# S503.6 Windows static Whisper notice review

Candidate: [native build run 40207606199](https://github.com/qiangli/bashy/actions/runs/40207606199) at Bashy `2a490dbf`; [binary/import/attestation ledger](windows-static-whisper-40207606199.json). The reviewed Windows amd64 binary SHA-256 is `ed76f5b84b70bdcb93568b4f2819d698ad9b43857a2b249f335da90790b51882`; arm64 is `3240d7f6899ddf77c6f304ad36bdfa4fc4f30246dd214e281094062b6291054d`. Both PE import tables list only Windows OS and UCRT DLLs, with no dynamic MSVCP, VCRUNTIME, libc++, libunwind, winpthreads, GCC or OpenMP DLL. [Microsoft documents UCRT as part of Windows 10 and later](https://learn.microsoft.com/en-us/cpp/porting/upgrade-your-code-to-the-universal-crt?view=msvc-170). This is an import result, not a complete static object license audit.

COFF symbols and DWARF compile units in both binaries show linked libc++, libc++abi, libunwind, compiler runtime helpers, MinGW CRT and David Gay `gdtoa` code. Both contain `../gdtoa/gdtoa.c`, `strtodg.c`, `gethex.c` and `../math/ldexpf.c` compile units; amd64 also contains `../math/x86/ldexp.c`. The llvm-mingw 20260616 [ISC project license](https://github.com/mstorsjo/llvm-mingw/blob/20260616/LICENSE.txt) covers its assembly scripts, not the external components of the built toolchain or the linked executable. Its release workflow selects artifacts from a successful `push` build; the moving mingw-w64 master override in the build workflow is `schedule` only. This supports the default tag's `c28e9555bb8800c53449f42a465ad9a5676fce88` source pin for the release zips, but the reviewed binary artifacts contain no archive-member link map or included notice bundle. The MinGW runtime notice also contains an unresolved Cephes math permission `FIXME`; no Cephes compile unit was found in these binaries, which does not rule out embedded objects or inline code.

Before product admission, collect the linker map or equivalent archive-member/object provenance from both native Windows builds, reconcile every non-project linked object against this notice set, resolve any Cephes or Wine-derived code that is actually linked, and package the applicable notices beside the binaries. The `gpl_free: true` build-report field and PE import scan alone do not establish that outcome. Python's separate Windows VC prerequisite and a signed product release/install path remain open.
