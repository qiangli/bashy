# Story 266 landing 1 note

The request for one `coreutils/pkg/atlas` row per new `kb` subcommand cannot be
represented by the current atlas schema. Atlas records are keyed by executable
top-level command names and are ratcheted against the tool/front-door
registries. Subcommand-bearing commands deliberately have one row (the same
rule already documented for `ast` and `graph`). Adding rows named `context`,
`doctor`, or `observe` would classify different top-level commands or fail the
registry coverage ratchet; names containing spaces such as `kb context` are
not registered commands at all.

No coreutils diff is needed or valid for landing 1. The existing row is already
the required classification:

```diff
--- a/pkg/atlas/atlas.go
+++ b/pkg/atlas/atlas.go
@@
+addVerb("kb", Entry{Stage: StageCross, Group: GroupKnowledge, Caps: []string{CapJSON}})
```

Bashy's atlas synopsis and `docs/command-atlas.md` now enumerate the stage
subcommands and flags on that row, and a test ratchets the row to
`GroupKnowledge` plus `CapJSON`.
