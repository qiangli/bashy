# Bashy v0.22.0

Release candidate notes, 2026-09-08. Changes since v0.21.0.

Bashy v0.22.0 adds Bash++ transpilation to standalone Go programs and shared
resource observation for sprint managers. The minor version follows the
[versioning policy](../release-roadmap-and-versioning.md): the new transpiler
extends the public language/tooling surface beyond backward-compatible fixes.
Existing experimental agentic features retain their current stability tier.

## New functionality

- `bashy transpile --bashpp input.bpp -o output.go` emits Go source and source
  maps, reports source-positioned diagnostics, and publishes outputs with
  rollback on failure. Imports resolve relative to the input source. Follow
  the [standalone build recipe](../transpile.md) to pin the compiler/runtime
  dependency and build the emitted program with Go 1.27.
- `bashy sprint monitor` combines shared host observations, workload identity,
  and model-account usage with explicit freshness and unknown states. Weave,
  Chat, and explicitly expensive scheduled work reserve capacity before
  launch when configured policy requires it. See the
  [resource-management delivery notes](../sprint-138-delivery.md) for commands,
  policy, evidence, and operational limits.
- Sprint stage changes can address seated conductors through the message
  board. `mb send --role conductor` resolves the current sprint records and
  reports invalid or unresolved selectors. Recurring sprint workflows gain
  `sprint advance` as their cycle boundary.

## Fixes and build integrity

- Numeric `date` formats, including release timestamps such as `%Y%m%d-%H%M`,
  work under an ordinary `LANG` without requiring embedded locale names.
  Formats that actually need unavailable locale data still fail explicitly.
- The embedded Meet UI matches its source. A required freshness check rebuilds
  the SPA and compares bytes and the complete file set without replacing the
  tracked artifact; local test entrypoints and Linux CI enforce it.
- Sprint watchers process room updates incrementally, bound acknowledgment
  work, and release attached leases on termination. Room storage honors
  `BASHY_HOME`, keeping isolated runs out of the shared board.
- Process teardown keeps cancellation active while descendants hold pipes,
  joins control workers, and retains resource reservations until termination
  is verified. Workspace cleanup preserves dirty, shared, active, and
  uncertain work.
- Native Windows fixtures cover resource admission and executable identity;
  transpiler tests preserve standalone execution and rollback behavior across
  platforms.

## Compatibility and limitations

The shell coordinate remains GNU Bash 5.3; the module compatibility floor is
Go 1.26.5, the selected development toolchain is Go 1.27.0, and release CI
selects Go 1.27.1. The Bash++ source profile uses Go 1.27 constructs and does
not promise acceptance of arbitrary Go source. Typed-only emitted programs
can run without a shell or source files; dynamic external commands still
require their executables on `PATH`.

Model usage is exact only where the configured provider supplies authoritative
data. Unsupported providers and uncertain demand remain visible as unknown;
machine-local reservations are not distributed quotas. Guarded remote work
remains queued on unsupported platforms. Executable hashes do not attest
descendants or shared libraries.

The release archive matrix is Linux, macOS, and Windows, each on amd64 and
arm64, for both `bash` and `bashy`. Archive availability, actual runtime QA,
and formal certification are distinct claims; these notes do not announce a
new certification award or a stability-tier graduation.
