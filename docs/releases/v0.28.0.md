# Bashy v0.28.0

Pre-1.0 minor release candidate following v0.27.0. Classic Bash remains the
default language mode. This release updates the pinned shell engine and fixes
the cross-platform behavior exercised by the Sprint 250 Go Tour, Go by Example,
and BashSharp Tour gates.

## Agent workflows

- Named resource claims make shared-host work visible to other agents and hold
  a claim across a bounded command.
- The pinned Yoke chat surface adds Enter submission while steering a live
  session.

## Bashsharp Archive bundles

- `bashy run app.bar` runs a ZIP or TAR bundle whose root `dag.md` declares a
  `main` target. Bashy caches each content version by SHA-256 and forwards
  extra arguments through `BASHY_BAR_ARGS_JSON`.
- Archive extraction rejects traversal paths, links, special files, duplicate
  entries, and oversized bundles. `bashy run` also accepts a DAG file or
  directory directly, with `--target` selecting a target when needed.

## Shell and Go-source execution

- Go-source execution preserves the caller environment while keeping
  launcher-internal signal coordination out of the program's environment.
- The Bash# callback bridge uses a bounded mailbox path for small replies and
  preserves the ordered pipe fallback for larger replies. The original Go Tour
  `solutions/image.go` callback workload remains subject to the 60-second
  per-step limit.
- The pinned engine repairs Windows native error-interface comparison,
  callback cancellation, and Go-source transpile timing and path handling.
- In GNU Bash-compatible POSIX mode, a readonly variable assignment before a
  command fails and discards the rest of that physical line. Commands on
  following lines still run, matching GNU Bash's shell error boundary.
- The pure `bash` release archive now also contains `sh`, a separate strict
  POSIX shell binary for conformance use. `bash` retains GNU Bash behavior.

## Managed tools and paths

- Cached Podman dispatch recovers its managed helpers on macOS, including
  distinct helper cache keys for separate Podman installations.
- Windows transpile accepts MSYS drive paths at its CLI boundary; native
  subprocess environment and shell startup paths retain their platform
  spellings.

## Evidence and scope

The pre-release candidate is gated by the serial GNU Bash 5.3 fixture suite,
three-OS `test` CI, tag conformance and native airgap images, published-byte QA
on macOS, Linux, and Windows, and all six BashSharp Tour runner legs. Exact
candidate and sibling commits, receipts, and any exceptions are recorded in
the Sprint 250 release evidence. These gates must pass before promotion.

This release adds no new compatibility profile or certification claim.
The public Bash# text and manifest fence syntax introduced in v0.27.0 is
unchanged.
