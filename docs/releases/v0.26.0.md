# Bashy v0.26.0

Pre-1.0 feature release expanding the opt-in Bash# Python and Rust runtime.
Classic Bash remains the default language mode.

## Python and Rust

- Persistent Python generators and Rust iterators can be consumed with range.
  They preserve module state and separate earlier values from a later error.
  Early exit closes the iterator; cancellation terminates and reaps blocked
  workers through the existing process lifecycle.
- Python TextIO filters compose with byte pipelines. Streams use the same
  bounded process channel as live process handles, with backpressure and
  explicit cleanup. Python text output uses LF across hosts; explicit binary
  writes retain their bytes.
- Python files can be imported by path and exported functions invoked as shell
  commands. Structured errors retain causes and remain distinct from worker or
  transport failures.
- Rust supports structured values, owned opaque handles and bounded callbacks
  into shell functions. Stale handles are rejected after release or worker loss.
- `run().Lines()` iterates captured output; `start().Lines()` streams live output
  with explicit `Wait()` and `Close()` lifecycle operations.

## Validation and discovery

- Registered script schemas validate typed arguments, defaults and allowed
  values before the body runs, including direct CLI and POSIX entry points.
- `@go.error` supplies typed value/error behavior through the existing decorator
  phases. `@timed` reports timing while preserving results and status.
- `define` describes live Bash# values without evaluating expressions or exposing
  opaque pointer identities.
- The decorator catalog documents supported decorators and the `@effects` /
  `@guard` contracts. Earlier airgap build and collaboration improvements are
  included through the pinned sibling revisions.

## Scope and limitations

Python/Rust integration remains an opt-in pre-1.0 profile. A project uses its
one declared, provisioned tool environment; this release adds no environment
manager. Structured JSON capture remains explicit through `json.Decode`.

Foreign pipeline commands must be statically resolvable. One persistent module
cannot occupy two concurrent pipeline stages; separate modules can, and
sequential calls in one stage are supported. Unix process-group and terminal
signal behavior applies on Unix; Windows uses its native process lifecycle.
The bounded channel is an internal runtime contract, not a new public channel
receive/select syntax.

Exact component revisions are recorded in `.sibling-pins`. Compatibility claims
are limited to the measured release profiles; this release does not claim an
Open Group certification award.
