# Bashy v1.0.0-rc.20

Development candidate for the bashy product pair. The release tag builds bashy,
outpost, bash, and sh from one pinned source graph. rc.20 is the first
candidate the promotion workflow can publish as a release-candidate tag.

## Release

- Promotion accepts release-candidate versions: `promote.yml`, the install
  channel generator and the product-release registration take `vX.Y.Z-rc.N`
  (and its `-dev` candidate). Homebrew, Scoop and Winget manifests carry the rc
  version string verbatim.
- The tier verdict is passed to promotion as an https URL pinned to a commit.
- The release QA lane reports exact pass, fail, known-failing and skipped
  counts, and fails a known failure that names no story and due date.

## Collaboration tools

- `matrix-chat`: setup and a live protocol end-to-end test; a cloudbox
  account shim gives ordinary users appservice-scoped accounts; reruns keep
  existing accounts.
- `whiteboard` and `brainstorm`: independent shared tools with browser
  end-to-end tests. Reads of a missing board or session return 404; only
  create makes one.

## Windows

- Bash# fleet fences (model, tool and agent, inline and embedded) run bashy
  through its native program path instead of an MSYS `/c/...` path.
- The LLM budget meter maps an MSYS `BASHY_LLM_BUDGET_STATE` to a native path.

## Fixes

- Formatted help resolves registered commands.
- A failed tool-archive extraction no longer poisons the binmgr cache.
- Skill text: generic fast-loop release practices, and the workplace rule
  (watch the inbox, answer promptly, announce before using shared hosts,
  checkouts or pins).
- Sibling pins move to the current yoke head.
