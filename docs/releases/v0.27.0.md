# Bashy v0.27.0

Pre-1.0 feature release: Bash# fences now carry text artifacts and project
manifests, not only code, and a runner of your own can process any fence.
Classic Bash remains the default language mode.

## Text fences

- `~~~<type> [as <alias>] [!<runner>]`: the body is an artifact and the alias
  exposes the verbs of its processor, declared by a built-in row or by the
  runner's `methods` answer — never guessed from the body. Rows: `dockerfile`
  (podman), `tf` (OpenTofu, provisioned), `k8s` (kubectl; `play`/`down`
  through podman locally), `helm`, `dag` (a script carries its own pipeline;
  targets are methods), `skill` (a SKILL.md as a private ring); `compose` is
  reserved and refuses by name.
- Every verb carries effect atoms; `@guard` denies a call whose effects exceed
  the cap with status 126 before the processor runs, and binds the zero value
  so a `:=` site stays well-formed.
- A `!runner` is a Bash# function of the unit, a shell function, or a command
  registered with `bashy commands add`/`register`; a program on `PATH` is
  never a runner. The body materializes under the cache, never in the tree.

## Manifest fences

- `~~~cargo`, `~~~pyproject`, `~~~gomod`, `~~~cmake`, `~~~makefile`,
  `~~~package`: a script carries its Cargo.toml / pyproject.toml / go.mod /
  CMakeLists.txt / Makefile / package.json and drives the toolchain bashy
  provisions from the caller's directory. Nothing is written into the
  caller's tree: shadow projects (cargo, npm) or native out-of-tree flags
  (`uv --project`, `make -f`, `cmake -S/-B`, `go -overlay`) keep the
  manifest, caches and outputs under the fence root.
- `bashy zig` fronts the toolchain already provisioned for the C fences;
  `bashy commands register` is an alias of `add`.

## Lowering

- A Bash# `func` runner with the runner signature lowers with the program
  (`bashy transpile`); a shell-function, registered-command, `dag` or `skill`
  runner is interpreter-only and refused by name with the route. A transpiled
  binary never depends on a shell on the target.

## Naming

- `.bsh`, `--bashsharp`, ```` ```bsh ```` are the spellings the docs promote;
  `.bpp`, `--bashpp`, `BASHY_BASHPP`, ```` ```bashpp ```` remain silent aliases
  (no notice, no deprecation mechanism).

## Scope and limitations

No lowered program carries an effect cap plane yet: the 126 boundary is the
interpreter's, and a built-in row's effects are ungated when lowered.
`kubectl` verbs are wired but were exercised only through the local
`podman kube play` target. Exact component revisions are recorded in
`.sibling-pins`. Compatibility claims are limited to the measured release
profiles; this release does not claim an Open Group certification award.
