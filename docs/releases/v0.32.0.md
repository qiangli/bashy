# Bashy v0.32.0

Pre-1.0 minor release following v0.31.0. Classic Bash remains the default
language mode. This is the first release cut as **one product from one tag**:
the bashy tag now builds bashy, outpost, bash and sh together from one pinned
source graph, and a single download installs the whole system.

## One download, two roles

- Each `bashy-<os>-<arch>` archive now contains four executables: `bashy`,
  `outpost`, `bash` and `sh` (`.exe` on Windows). Raw `outpost-<tag>-<os>-<arch>`
  binaries and their SHA256 sidecars ship beside them in the same release, so
  existing outpost upgrade paths keep working. Outpost no longer has its own
  release; its version is the bashy tag.
- `bashy self install [--dir D] [--service]` installs the four executables
  side by side and, with `--service`, registers the outpost service. No Go
  toolchain and no separate installer script are needed.
- bashy and outpost find each other next to themselves first, then through
  the documented override, PATH and user directories. Each one checks its
  sibling's version against its own build stamp, and `bashy outpost` runs
  the matching outpost.
- `outpost upgrade` applies the pair: it stages and verifies both binaries,
  swaps bashy first and outpost last, and undoes the swap if any step fails.
  `outpost rollback` and the supervisor watchdog restore both binaries.
  Single-binary upgrades from older outposts still work.
- One shell: browser, SSH and outpost shell sessions now run the sibling
  `bashy`. Outpost no longer embeds a second shell implementation.
- bashy no longer imports outpost. The peer SSH client and server packages
  moved into the shared yoke library, so bashy's dependency closure carries
  no outpost code and no yamux.

## Offline installs

- Installing from the archive works without network access for everything
  bundled in it. Managed tools are looked up in the local cache before any
  network fetch, and `BASHY_OFFLINE=1` turns a would-be download into a clear
  offline error.
- Seed caches: export a verified tool cache on a connected machine and import
  it on an air-gapped one; imported entries are checksum-verified.

## Install channels

- Homebrew formula (with a `brew services` block), Scoop manifest and Winget
  manifest are generated from the verified release archives at promotion.
  They contain no install logic of their own.

## Agents and tooling

- `bashy ycode` hosts the native ycode TUI over the builtin genie engine;
  literal lines run on bashy.
- Governed fleet fences: agent, model, tool and skill fences with inline and
  embedded definitions, scoped clones and spend caps.
- Built-in MCP server: front-door verbs as policy-gated MCP tools, session
  tools with bounded output, and an HTTP transport alongside stdio.
- Structured command-not-found hints on the runtime exec path.

## Licensing

- The tree-sitter grammar set moved to a blob-free fork, and the GPL/MPL
  grammars were dropped. bashy stays permissive-only.

## Fixes

- Rejected `OUTPOST_SSH_PASSWORD` no longer falls back to a blocking TTY
  password prompt.
- Sprint disk-capacity checks use the configured workspace storage and no
  longer report a false 100% full disk.
- Relocatable product builds require `-trimpath`; cached toolchains relocate
  correctly for product runtime overlays.
