# bashy v0.23.0 — the first Bash# release

Pre-1.0. This is the release the Bash# tour ([qiangli/bashsharp-tour](https://github.com/qiangli/bashsharp-tour))
is written against; its gate runs against the latest bashy release on Linux,
macOS and Windows and is the acceptance check for this one.

## Bash++ is now Bash#

The language bashy speaks with the flag on is renamed **Bash#** (`bashsharp`):
rail5's Bash++ — bash with classes — has that name, the `bpp` binary and the
`.bpp` extension, and had them first.

- `--bashsharp` / `--no-bashsharp`, `BASHY_BASHSHARP`, `set -o bashsharp`,
  and the `.bsh` extension are canonical. The Bash++ spellings
  (`--bashpp`, `BASHY_BASHPP`, `set -o bashpp`, `.bpp`) still work as
  deprecated aliases for one minor release; a notice is printed only when
  stderr is a terminal.
- The language front door (dialect selector, direct Go-source interface,
  `transpile`) now lives in its own module, [qiangli/bashsharp](https://github.com/qiangli/bashsharp),
  which bashy imports. The engine (parser, evaluator, lowering) stays in
  [qiangli/sh](https://github.com/qiangli/sh); engine identifiers keep their
  `BashPP` spelling on purpose.
- `examples/quickstart/` — the ten-minute offline demo: one `agentic`
  function under `@guard`/`@require`/`@ensure`, six calls, six exit codes,
  and `check.sh` to diff it on the installed binary.

## Language and runtime since v0.22.0

- Contracts (`@require`, `@ensure`, `@guard`) on shell functions, typed
  functions and `agentic` functions; a failed clause exits 3 and names
  itself; status 6 from an `agentic` body is a yield (input required) and
  runs no postcondition. `bashy agentic` runs an action under those rules.
- Decorators (`@name(args)` over a declaration; the decorator takes
  `c *Call`) with native `trace`/`guard`/`retry` and registration-time policy
  advice (`bashy inspect advice`).
- Keyword and default arguments, exhaustive enums, deep `readonly`, and the
  null-safety checker (`bashy check`) — the Bash# ergonomics tier.
- Fenced islands: `~~~python`, `~~~typescript`, `~~~rust`, `~~~c`/`~~~cpp`,
  `~~~go` (compiled with the nearest `go.mod`'s toolchain) and
  `~~~bash`/`~~~sh` dialect islands, callable from shell text; `bashy dag`
  front doors for real repositories under `examples/dag/` (uv, Codex, Bun,
  OpenCode, OpenClaw, Hermes Agent, curl, git, FFmpeg, tesseract, llama.cpp,
  CMake, gh, Hugo, Caddy, mise, nanochat, mini-swe-agent).
- Whole Go programs via `--source=go`; leading-package Go units; `transpile`
  hands test units their package.
- `bashy awd DIR -- CMD`, the one directory mechanism for dag bodies.
- Registered commands: `bashy commands add|set|rm|edit|verify|show|list`
  make your own command a first-class shipped-like command, answering
  `type`/`command -v`.
- `bashy dag <target>` no longer exits 0 silently when a mounted subcommand
  shadows the target name.
- POSIX-mode grammar selection is explicit and consistent in interactive and
  non-interactive sessions; classic option listings are preserved with the
  dialect on.

## Building from source

`bashy` rebuilds itself using only an installed bashy: `bashy git clone`,
`bashy scripts/bootstrap-siblings.sh`, `bashy dag build`. On Windows that
needs no git, no Go and no C compiler — bashy provisions a pinned MinGit and
its own Go toolchain. On Linux and macOS the platform `git` is used; a C
compiler is optional and only adds the native signal launcher (without one
the build says so and ships the plain Go binary, the same form the release
archives ship). `go install github.com/qiangli/bashy@latest` is not
supported and the README no longer claims it. `scripts/bootstrap-siblings.sh`
now moves a clean standalone sibling to the pinned commit when `.sibling-pins`
has moved (it used to leave a stale sibling in place and build against it);
umbrella submodules and siblings with local changes are left alone and said so.

## Fixed on the way to this release (found by the release QA on published bytes)

- `x=$(cmd 2>&1)` now keeps stdout and stderr in write order (the capture
  runs through one real pipe, as bash's fork does); a `/bin/sh` child used
  to come back `err1 err2 out1 out2`.
- `bashy check --bashsharp` is accepted (the rename had missed `check`).
- Windows: `mktemp` and `rmdir` resolve the `/c/…` paths bashy hands out for
  `$TEMP`, `$HOME` and `pwd`; the build recipe runs its helper scripts
  through bashy, since Windows has no `/bin/sh` to honour a shebang.
- `ls`, `comm`, `join`, `expr` and `csplit` run under the macOS default
  locale (`en_US.UTF-8`) and the Linux default (`C.UTF-8`), like `sort`,
  `sed`, `grep`, `tr` and `cut` already did.

## Compatibility and evidence

- GNU Bash 5.3 own test suite: 86/86 runnable fixtures on macOS with the
  dialect off (the release gate, run serially on the tagged commit).
- With the dialect on: 79 + 7, the seven being fixtures that name a shell
  function `func`.
- The Bash# tour gate: 26 required checks on the tagged bytes.
- These results are compatibility evidence, not POSIX certification.

## Known limitations

- Job control and some interactive corners remain incomplete; the README's
  compatibility notes list them.
- The Windows archive ships the plain Go executables; the full Bash test
  suite is not yet measured on Windows.
- Transpiled Go imports the engine's `shellrt` runtime, which only the
  `qiangli/sh` fork provides; building the emitted program from a clean
  machine needs a checkout of that module (tracked for a later release).
- Coreutils applets carry exactly two host-default UTF-8 locales as C
  semantics with UTF-8 text: `C.UTF-8` (any spelling, every platform — the
  Debian/Ubuntu/musl default, new in this release) and `en_US.UTF-8` on
  macOS. Any other `*.UTF-8` locale is reported and refused by the locale-
  sensitive applets (`grep`, `tr`, `sort`, `cut`, `sed`, …); set
  `LC_ALL=C.UTF-8` on such hosts.
