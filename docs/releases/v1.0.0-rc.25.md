# Bashy v1.0.0-rc.25

Development candidate for the bashy product pair. The release tag builds
bashy, outpost, bash, and sh from one pinned source graph. Candidate:
**v1.0.0-rc.25-dev**, commit SHA **TBD at freeze** — the freeze pins one
commit and builds it once, and promotion reuses the tested bytes. The
sections below are the changes new since `v1.0.0-rc.24-dev`; the
[known-issues ledger](v1.0.0-rc.25-known-issues.md) records every open,
pending and blocked item on this candidate, the operator signs it before
promotion, and promotion itself is a separate, explicitly approved step.

## Software shaping

- `bashy shape` is the CLI front door to the full shaping lifecycle: `wish`
  (isolated candidate generation, or `--from` a workspace) → `verify` →
  `preview` → `approve` through the sealed activation gate → `undo` /
  `restore`, plus `submit`, which opens a reviewable source proposal and an
  ordinary weave through the existing gates — it never merges by itself.
- CLI- and service-kind apps shape with build/test argument vectors held
  outside candidate source. Native versions activate through immutable side
  slots while the installed release and PATH stay intact.
- bashy itself is shapeable: `shape status`, `undo` and `restore` for bashy,
  and the authoritative control paths always execute the retained released
  implementation, so recovery never depends on a healthy shaped CLI.
- The same lifecycle reaches the paired console's remote API, and the shared
  shaping engine works in a standalone bashy.

## Harness, repairs and supply chain

- Repair profiles: every conformance suite runs through the bashy/Bash#
  runtime with bashy's own POSIX utilities on the suite PATH, `-list` fails
  closed on an empty `-only` selection, and the outpost profile tests the
  shipped `CGO_ENABLED=0` build.
- Process supervision fixes: a Linux process counts as live until every
  thread exits; captured orphan-group members are joined before reclaim;
  unknown process liveness is never read as an exit; malformed proc
  identity fields are rejected.
- Shell runtime repairs consumed through pins: virtual-subshell self-signal,
  command-substitution EXIT trap, strict POSIX getopts and asynchronous
  EXIT, bounded unset scanning, indexed arithmetic, alias grammar, Sh
  pointer metadata race, SQLite object write transactions, Bonsai log
  rotation.
- The tree moved onto standalone module pins; shrink-only import ratchets
  guard the `cmd/bash` and core/cert-base import graphs.
- The local-model Ollama engine's CUDA runner ships per-tool prereleases
  with `libggml-cuda.so` (`$ORIGIN` RUNPATH, audited closure, host-required
  NVIDIA runtime libraries) and is admitted by a checklist record instead
  of an unconditional hold.

## Extending this release: software shaping

rc.25 is released as a shapeable minimum: features and fixes that land after
this release arrive as **shaped changes**, not waiting for the next tag. A
shaped change is generated into an isolated candidate, verified, previewed
and approved through the sealed gate, and stays reversible with
`bashy shape undo` — a host adopts post-release work without rebuilding its
installed release.

Shaped changes are promoted along three tiers — the **local** host, the
**team/org** remote, and **upstream** (the bashy repo) — with git-like
ergonomics in both directions:

- `bashy shape outgoing` and `bashy shape push --to org|upstream` list and
  promote approved, verified local shapes toward the team/org remote or
  upstream (upstream through a reviewable source proposal). *If included at
  freeze — see known issues G6.*
- `bashy shape incoming` and `bashy shape pull --from org|upstream` list and
  adopt changes available from the team/org or upstream through the same
  gated lifecycle, from the side slot, still undoable. *If included at
  freeze — see known issues G6.*

The local lifecycle (`wish` → `verify` → `preview` → `approve` → `undo`) is
in this candidate. The promotion rod above is Sprint 580 story P1: if it
misses the Saturday-noon cut, rc.25 freezes without it, the rod becomes the
first shaped change after release, and ledger rows G6/G7 are the record.

## Install and verify

- Download the `bashy-<os>-<arch>` archive from the candidate release and
  verify it against the release's `checksums.txt`. One archive carries
  `bashy`, `outpost`, `bash` and `sh` (`.exe` on Windows); raw outpost
  binaries ship beside them with SHA256 sidecars.
- `bashy self install [--dir D] [--service]` installs the executables side
  by side and, with `--service`, registers the outpost service. No Go
  toolchain and no separate installer script are needed. Offline installs
  and seed caches work as in v0.32.0.
- Verify the stamp: `bashy --version` reports `5.3.0(1)-bashy-<tag>` on a
  stamped build — the candidate carries its `-dev` tag — and
  `5.3.0(1)-bashy` on an unstamped development build.
- Package channels (Homebrew, Scoop, Winget, Linux `.deb`/`.rpm`/`.apk`)
  are generated from promoted release bytes only, never from candidate
  `-dev` bytes.

## Known issues and security boundary

The complete ledger is
[v1.0.0-rc.25-known-issues.md](v1.0.0-rc.25-known-issues.md); the operator
re-approves it before promotion. Headlines:

- **Documented security limit (KI-2, no test skipped):** bashy's own child
  programs inherit genie's `@guard` network deny and fail closed;
  **non-bashy child programs can escape that deny** — they need a declared,
  granted `@runs`, and only explicit `@sandbox` gives real containment.
- KI-1: an explicit `@sandbox()` island still fails closed against a
  doubled-`bashy` argv0/ENTRYPOINT (native Windows exit 126) — open, P0.
- KI-4: the inherited `SIG_IGN` repair is in-tree and green in this
  workspace; the licensed `sh` TP164 re-run remains the acceptance leg.
- KI-10: `make test-bash` is 83/86 with `LANG` unset; the freeze gate pins
  and states the locale instead of hiding that entry mode.
- G6/G7: the shaping promotion rod and its round-trip legs are pending at
  the cut (see *Extending this release*).
