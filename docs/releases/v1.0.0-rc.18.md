# Bashy v1.0.0-rc.18

Development candidate for the bashy product pair. The release tag builds bashy,
outpost, bash, and sh from one pinned source graph. It carries the
v1.0.0-rc.16-dev outpost changes (which shipped without notes) and makes the
test workflow green on Windows, macOS and Linux. (v1.0.0-rc.17-dev was a
candidate only; its Windows QA found the registered-command fix below.)

## Outpost

- The upgrade watchdog also acts while the new daemon is running: a candidate
  that stays up but never confirms healthy is stopped and rolled back to the
  previous binary shortly after its confirm deadline, without a restart or
  reboot of the host. A rollback that cannot proceed (no usable previous
  binary) stops the daemon at most once per pending upgrade instead of every
  check interval.
- Direct `outpost ssh` dials (LAN, explicit `host:port`) offer key auth first
  and fall back to `~/.ssh/id_ed25519`, `id_ecdsa` and `id_rsa` when an SSH
  agent is configured but unreachable or empty. Password auth stays the last
  resort.
- Direct dials pin host keys per `host:port` and refuse a changed key by
  default; `OUTPOST_SSH_STRICT_HOST_KEY=0` restores re-pinning.

## Bashy

- `bashy connect <host>` opens an interactive shell on a host through outpost
  SSH.
- `examples/outpost-profile`: a Bash# command (skill and script) that keeps one
  outpost pairing per satellite and switches between them
  (`outpost-profile add|use|list`), using only `outpost register --out` and
  `outpost restart`.

## Fixes

- Windows: a registered exec command whose path is written in MSYS form
  (`/c/...`) is found (its presence check resolves the native path and
  executable extensions), instead of reading as not installed.
- Windows: the exec episode recorder closes each record's file, so the file
  is no longer held open after the command ends.
- Windows: a watcher inside its own managed session is recognised as the
  owner (process ancestry is read on Windows too).
- `docs/airgap-image.md` matches what the airgap gate measures; absent cloud
  CLIs (`aws`, `az`) are reported as not usable offline, by design.
- Sibling pins move to the current coreutils, yoke, outpost, bonsai, sh and
  ycode heads.
