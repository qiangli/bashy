# bashy v0.24.1

Pre-1.0 patch release.

## Fixed

- **A command launched from a bashy prompt inherits the terminal.** Output
  shaping wrapped the shell's stdout/stderr for every run, so a foreground
  external command was handed a pipe instead of the terminal: `codex` exited
  with "stdout is not a terminal", `claude` fell into `--print`, and `vim`,
  `less`, `ssh` and other terminal programs degraded the same way — on every
  OS, loudest on Windows. A terminal sink is now passed through unwrapped;
  output captured for a harness reading bashy through a pipe is unchanged, and
  an explicit `BASHY_OUTPUT_REDUCE=on` / `--reduce` still captures.
  `test -t 1` from a bashy script on a terminal answers true again.

## Since v0.24.0 (bashy's agentic surface, via the yoke pin)

- `bashy inbox` / `mb` / `ping` / `notify` reach colleagues on other hosts
  through the shared sprint session; the inbox says how fresh the relay is.
- A message to a live seat is delivered to that seat, never to a one-shot
  launch under the same name; a sprint's room opens when it moves into doing.
- The apps console binds with a symbolic `--bind lan` (phone pairing follows
  the network); the service daemon recognises `WSAECONNREFUSED` on Windows.
- The Bash# language module is imported from the `bashsharp` organisation
  (`github.com/bashsharp/bashsharp`); tour links follow the rename.
