# Bashy v0.30.0

Pre-1.0 minor release following v0.29.0. Classic Bash remains the default
language mode. This release adds the host's model door, contained calls,
the genie agent front door and registered apps, and restores exact GNU Bash
script-file error behaviour.

## New

- **`bashy llm` — the host's one model door** (port 24556). Local models run
  on bashy's own Ollama engine as an exclusive device with a priority run
  queue; the fleet's CLI seats (claude, codex, agy, …) are served through
  the same door by band, model or agent name. Clients authenticate with the
  owner token; `bashy llm env` prints the OpenAI, Anthropic and Ollama
  client variables. Sticky bindings freeze one exact instance for benchmark
  arms. A codex seat now costs one model request per door call (every codex
  tool is off), and stopping the door leaves no worker directory behind.
- **Contained calls.** `@contain` / `bashy contain --net deny` run one command
  with enforced network isolation: native where the OS has it (Linux network
  namespace, macOS Seatbelt), else bashy's own FROM-scratch image with no
  network. `provider` selects builtin, native, image or custom. A pinned
  third-party image runs as one contained call (`@contain(image: ...)`,
  `bashy contain --image`, `contain pin`); read-only mounts accept Windows
  host paths.
- **`bashy genie`** — a front door for the local-model SWE agent (one-off,
  piped, interactive and web modes; `-m MODEL`), built in from linked source,
  with `genie doctor` reporting the engine and the model door.
- **`bashy app add/show/set/rm/edit`** — registered apps with custom
  launchers.
- **`bashy stats`** — resolve rates, paired confidence intervals, pass^k and
  cost per solve for agent benchmark runs.
- **`bashy ycode`** — the YAML agent engine, in process.
- `self image --with python,go` builds preloaded toolchain variants; the
  FROM-scratch image and the toolchains it runs carry CA roots.

## Fixes

- GNU Bash script-file error semantics. After an arithmetic or expansion
  error, a script resumes at its next line, as Bash does; the engine
  developed since v0.29.0 had copied the `bash -c` one-line behaviour into
  scripts and exited instead (never released). The fix also covers `$((...))` error tokens (they keep the
  source's trailing whitespace), `[[ -v a[$k] ]]` with a bracketed key,
  `BASH_COMPAT=51 unset a[@]`, `caller` for the outermost frame, and
  `declare -f` line breaks inside `$((...))`.
- `podman machine start` runs from the home directory, not the caller's
  working directory; engine passthrough forwards termination signals.
- `sh -n` / `bashy -n` parse only.
