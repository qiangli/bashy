# S8 clip — delivery evidence (Sprint 631)

Story S8 clip (#214, `032b83ec6219`): an asynchronous clip library —
queue a cut from a video, a terminal scene or the screen; render in the
background; take the finished path. Base for the media family: scenes from
`examples/cast`, takes from `examples/record`, storyboards from
`examples/video`, publishing from `examples/vlog`.

## Decision: build

The sprint's candidate review (private spec) found no qualifying
permissive app with ≥1k stars for this job: the leading open-source
screen recorders are AGPL or GPL, two candidates are macOS-only clients,
and the remaining MIT projects are under 1k stars. Per the fork-or-build
rule the job ships as original code in `examples/clip`.

## Name

The command registers as **`clips`**: bashy already ships a `clip` skill
(the clipboard), and a registered command may shadow a PATH binary,
never a command bashy ships. The job, directory and module stay `clip`;
the app, command, skill and page say `clips`.

## License

Original code in this repository over a standard-library-only module
(`examples/clip/go.mod`); no third-party source is vendored, linked or
distributed. `ffmpeg` and `agg` are host tools located at run time
(`clips doctor` reports both) — the same run-never-bundle arrangement as
`examples/video`. No `ee/`, `premium/` or `enterprise/` directories.
Wording is job-only: no commercial product is named in any public file.

## Tests (targeted; QA is a separate pass)

- `GOWORK=off go -C examples/clip test -count=1 ./...` — ok: job store
  round-trip and validation, the render worker with injected tools
  (trim/cast/screen, failure paths, stale requeue), the page and its
  media route, the `shaped.json` contract, and the script driven end to
  end through a built bashy with a stub `ffmpeg` (skips in a vendored
  clone).
- `bashy dag examples/clip test` — ok (the same through the task graph).
- `go vet ./...` ok, `gofmt` clean.
- Real render on the dev box: the sample asciicast scene queued, rendered
  with the host `agg`, taken — a playable `.gif` in the library
  (`bashy dag examples/clip use` path).
- Scope: screen capture is an X11 job (Linux, this sprint); off Linux the
  job fails with the platform reason instead of hanging (covered by
  `TestQueueScreenForm`).

## Shaping demo (Shapeable badge)

Isolated bashy home with the product binary, the console on loopback
(`app serve --bind lan --pair`), two paired principals (alice, bob),
each with a finished clip in their private app data so the page has a
done row. All through the CLI (`UI → CLI parity`).

| Step | Command (abridged) | Result |
|---|---|---|
| register | `bash register.sh` | command `clips`, skill, shaped app `clips` (`app add --type shaped`, managed source in the isolated home) |
| wish | `bashy shape wish clips "Show a Loop badge on every finished clip" --from <hand-made workspace>` | candidate `185d4f6bc8681e9f` (base `a5bd901130a1`, rev `8f39e1ed9920`) |
| verify | `bashy shape verify clips 185d4f6bc8681e9f` | verdict **pass** — declared check `checks/go.bsh` builds and tests the module in the isolated clone |
| preview | `bashy shape preview clips 185d4f6bc8681e9f` | URL served; page has 1 `loop-badge` for the requester; the other principal's preview request → 404; both principals' **active** pages → 0 badges |
| approve | `bashy shape approve clips 185d4f6bc8681e9f` (alice) | approved; alice's page → 1 badge, **bob's page → 0 badges** (scoped activation, visible only to the requester) |
| undo | `bashy shape undo clips` (alice) | alice's page → 0 badges; history lists both revisions; active restored to base `a5bd901130a1` |
| negative | broken candidate `a0cb011c3b36b67f` (a failing test) | verify verdict pass=false ("verification failed"); `approve` exits 1; the active version is unchanged |

Badge checklist: registered with declared kind (`web`) through the public
shaped-app path; declared checks that can fail (the negative row);
activation scoped to a principal; undo and history work; every step above
has its CLI verb.
